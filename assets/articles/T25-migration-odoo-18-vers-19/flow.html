Flow migration Odoo 19 — pre · post · end
odoo-bin -u module · ordre d'exécution des scripts dans migrations/<version>/
Stage 1

pre

[>19.0.1.1.0]

AVANT le chargement du modèle par l'ORM.

  • ALTER TABLE
  • RENAME COLUMN
  • DROP constraint

Les colonnes doivent exister avec le nom attendu AVANT que l'ORM ne charge le modèle.

Auto

ORM load

odoo registry

Odoo charge les modèles, synchronise le schéma.

  • CREATE TABLE
  • ADD COLUMN
  • CREATE INDEX

Automatique — si la colonne existe déjà (grâce au pre), l'ORM la réutilise.

Stage 2

post

[19.0.1.1.0>]

APRÈS que l'ORM ait chargé les modèles.

  • UPDATE values
  • env via SUPERUSER_ID
  • recompute fields

env disponible via api.Environment(cr, SUPERUSER_ID, {}).

Stage 3

end

[$19.0.1.1.0]

APRÈS tous les modules (même les dépendants).

  • Cleanup final
  • Cron triggers
  • Assertions

Idéal pour invalidate cache + vérifier cohérence cross-module.

✓ OK

Module migré

v19.0.1.1.0

Schéma + data à l'état cible.

  • columns renommées
  • valeurs converties
  • tests PASS

Base cohérente, prête pour production.
