XPath en Odoo 20 : hasclass, move, attributes, replace sans casser

Cibler un bloc par sa classe, déplacer un champ, retirer ou compléter un attribut, masquer un champ sans faire tomber le module suivant : les quatre gestes XPath qui reviennent dans toute vue héritée, rejoués sur la fiche contact d'Odoo 20.

1. hasclass() plutôt que @class

En XPath, @class='alert-warning' compare la chaîne entière de l'attribut. Le bandeau des doublons de la fiche contact porte class="alert alert-warning oe_edit_only" : le test échoue. Odoo 20 fournit une fonction XPath maison, hasclass(), vraie quand l'élément porte toutes les classes passées, dans n'importe quel ordre. Ce script, passé à odoo-bin shell, compte les nœuds trouvés dans la vue combinée :

# hasclass.py
from lxml import etree
form = env.ref('base.view_partner_form')
arch = etree.fromstring(form.get_combined_arch())
for expr in ["//div[@class='alert-warning']",
             "//div[hasclass('alert-warning')]",
             "//div[hasclass('d-flex')]"]:
    print(len(arch.xpath(expr)), "nœud(s) pour", expr)

Dans une vue héritée, @class déclenche en plus un avertissement au chargement : Error-prone use of @class in view … use the hasclass(*classes) function. La troisième ligne rappelle l'autre règle : quand l'expression trouve plusieurs nœuds, Odoo ne garde que le premier. Une classe utilitaire comme d-flex est donc un mauvais repère : pars plutôt d'un nœud nommé, par exemple //field[@name='phone']/.. pour le bloc du téléphone. Même chose pour la forme courte <field name="email" position="…"> : elle vise le premier champ de ce nom.

2. attributes et move : retoucher sans réécrire

Voici la vue héritée du module d'exemple. Chaque bloc correspond à une requête qu'on tape dans Google :

<record id="view_partner_form_xpath" model="ir.ui.view">
    <field name="name">res.partner.form.mon_xpath</field>
    <field name="model">res.partner</field>
    <field name="inherit_id" ref="base.view_partner_form"/>
    <field name="arch" type="xml">
        <!-- ajouter des classes à celles qui existent -->
        <xpath expr="//div[hasclass('o_address_format')]" position="attributes">
            <attribute name="class" add="border rounded p-2" separator=" "/>
        </xpath>
        <!-- en retirer une -->
        <xpath expr="//div[hasclass('alert-warning')]" position="attributes">
            <attribute name="class" remove="oe_edit_only" separator=" "/>
        </xpath>
        <!-- compléter une condition Python -->
        <field name="lang" position="attributes">
            <attribute name="invisible" add="not is_company" separator="or"/>
        </field>
        <!-- supprimer un attribut : balise vide -->
        <field name="function" position="attributes">
            <attribute name="placeholder"/>
        </field>
        <!-- déplacer le poste sous le téléphone -->
        <xpath expr="//field[@name='phone']/.." position="after">
            <xpath expr="//field[@name='function']" position="move"/>
        </xpath>
        <!-- masquer le site web -->
        <field name="website" position="attributes">
            <attribute name="invisible">1</attribute>
        </field>
    </field>
</record>

Après -u mon_xpath, ce script lit l'arch combiné :

# voir_arch.py
from lxml import etree
arch = etree.fromstring(env.ref('base.view_partner_form').get_combined_arch())
for expr in ["//div[hasclass('o_address_format')]",
             "//div[hasclass('alert-warning')]",
             "//field[@name='lang']",
             "//field[@name='function']",
             "//field[@name='website']"]:
    node = arch.xpath(expr)[0]
    print(node.tag, dict(node.attrib))
fn = arch.xpath("//field[@name='function']")[0]
print("function dans :", fn.getparent().tag, fn.getparent().get("class"))

Ce qu'il faut en retenir :

  • add / remove travaillent sur une liste séparée par separator (virgule par défaut : pour class, écris separator=" "). Les classes d'origine restent, seule oe_edit_only est partie.
  • Sur invisible, readonly, required, column_invisible et decoration-*, le séparateur est un opérateur Python, and ou or : Odoo met les deux conditions entre parenthèses.
  • Retirer un attribut : <attribute name="placeholder"/> sans contenu. Une valeur vide supprime l'attribut.
  • move n'est valable qu'à l'intérieur d'un autre nœud de positionnement : le nœud est retiré de sa place et posé à la nouvelle. Écrit seul au premier niveau, il est refusé : Position d'attribut invalide : 'move'.

Le champ déplacé dans le group de l'en-tête y prend son libellé, « Poste ». La langue a disparu parce que ce contact n'est pas une société. Le champ « Référence » à droite vient du second module, au point suivant.

add sur invisible sans separator : plantage

Oublier separator="or" sur une condition Python ne donne pas une valeur par défaut : la création de la vue échoue sur AttributeError: 'NoneType' object has no attribute 'strip', sans un mot sur le séparateur manquant. Avec separator=" ", le refus est plus clair : Séparateur '' non valide pour l'expression python 'invisible'; les valeurs valides sont "and" et "or".

3. replace sans casser les autres modules

Pour cacher le site web, le premier réflexe est <field name="website" position="replace"/>. Le module s'installe, la fiche est juste. Puis vient un second module, mon_xpath_suite, qui ajoute un champ après le site web :

<field name="website" position="after">
    <field name="ref"/>
</field>

Les vues héritées s'appliquent l'une après l'autre (par priority, puis par id, donc dans l'ordre de création) : quand vient le tour de la seconde, le champ n'existe plus. Tout module installé après le tien et qui vise ce champ tombe ainsi, même s'il ne sait rien de ton module. Trois façons de remplacer sans retirer le nœud :

  1. Masquer : <attribute name="invisible">1</attribute>, comme au point 2. Avec cette version de mon_xpath, -u mon_xpath puis -i mon_xpath_suite passent, et « Référence » s'affiche sur la fiche.
  2. Envelopper : dans un replace, un élément dont le texte vaut $0 reçoit une copie du nœud remplacé. Le champ existe toujours, les autres vues le trouvent : 
    <field name="website" position="replace">
    <div class="o_mon_cadre">$0</div>
</field>
    Rejoué dans le shell avec la vue du second module, l'arch donne <div class="o_mon_cadre"><field name="website" …/><field name="ref"/></div>.
  3. Vider sans perdre les enfants : position="replace" mode="inner" remplace le contenu d'un nœud et garde le nœud lui-même ; un enfant à conserver se reprend par move : 
    <xpath expr="//div[@name='partner_address_country']" position="replace" mode="inner">
    <field name="country_id" position="move"/>
    <span class="o_mon_drapeau">FR</span>
</xpath>

Garde replace sans contenu pour les nœuds que ton module a lui-même ajoutés, ou que tu veux réellement faire disparaître en sachant qui les vise. Le shell te donne les vues qui héritent directement de la fiche, dans leur ordre d'application :

parent = env.ref('base.view_partner_form')
for v in env['ir.ui.view'].search([('inherit_id', '=', parent.id)], order='priority, id'):
    print(v.priority, v.xml_id)

À retenir

  • hasclass('a', 'b') pour les classes ; un xpath ne modifie que le premier nœud trouvé.
  • position="attributes" : add/remove + separator (or/and sur les conditions), balise vide pour supprimer.
  • position="move" se place toujours à l'intérieur d'un autre xpath.
  • Masquer plutôt que replace ; sinon $0 ou mode="inner" pour garder le nœud que d'autres modules visent.
