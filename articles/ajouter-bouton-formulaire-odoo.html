Ajouter un bouton dans l'en-tête d'un formulaire Odoo 20

Un bouton de plus sur le devis, à côté de « Envoyer » et « Confirmer » : une méthode Python sur le modèle hérité, une vue héritée qui vise l'en-tête, et quelques attributs pour la visibilité et la confirmation. Exemple complet sur sale.order, rejoué sur la démo.

~6 minutes de lecture · niveau intermédiaire · série Astuces dev Odoo 20

Édition : Community. Vérifié sur Odoo 20.0 Community, octobre 2026, base de démonstration (Ventes) et module d'exemple.

La réponse en bref

  1. Écris une méthode publique (sans _ devant) dans une classe _inherit = 'sale.order'.
  2. Crée une vue héritée de sale.view_order_form avec un <xpath> sur un bouton de //header, en position="before" ou "after".
  3. Déclare <button name="ta_methode" type="object"/>, plus invisible, groups, confirm au besoin.
  4. Mets le module à jour (-u mon_module) et rouvre la fiche.

1. La méthode que le bouton appelle

Le besoin d'exemple : un bouton « Noter une relance » sur le devis, qui écrit une note dans l'historique et confirme d'un message. Le module dépend de sale et étend le modèle :

# mon_module/models/sale_order.py
from odoo import models


class SaleOrder(models.Model):
    _inherit = 'sale.order'

    def action_noter_relance(self):
        for order in self:
            order.message_post(body="Relance téléphonique faite.")
        return {
            'type': 'ir.actions.client',
            'tag': 'display_notification',
            'params': {
                'title': "Relance notée",
                'message': "Note ajoutée à l'historique.",
                'type': 'success',
                'next': {'type': 'ir.actions.client', 'tag': 'soft_reload'},
            },
        }

Un bouton type="object" appelle la méthode sur l'enregistrement affiché : self est le devis ouvert. Avant d'écrire la vue, teste la méthode dans odoo-bin shell, sur le premier devis de la démo :

order = env['sale.order'].search([('state', '=', 'draft')], limit=1, order='id')
print(order.name, '|', order.partner_id.name)
action = order.action_noter_relance()
print(action['tag'], '|', action['params']['next'])
print(order.message_ids[0].body)
env.cr.rollback()
S00001 | Acme Corporation display_notification | {'type': 'ir.actions.client', 'tag': 'soft_reload'} <p>Relance téléphonique faite.</p>

Ce que la méthode renvoie décide de la suite à l'écran :

Valeur renvoyéeEffet constaté
True ou rienpas de message ; le formulaire est relu, la note apparaît dans l'historique
notification seule (sans next)la notification s'affiche, mais l'historique reste tel quel jusqu'au rechargement de la page
notification + next: soft_reloadla notification s'affiche et le formulaire est relu

D'où la clé next : le client web affiche la notification, puis exécute l'action qu'elle désigne.

2. La vue héritée qui place le bouton

Les boutons d'action d'un formulaire vivent dans <header>. La vue héritée vise l'un d'eux et se glisse à côté :

<!-- mon_module/views/sale_order_views.xml -->
<odoo>
    <record id="view_order_form_relance" model="ir.ui.view">
        <field name="name">sale.order.form.relance</field>
        <field name="model">sale.order</field>
        <field name="inherit_id" ref="sale.view_order_form"/>
        <field name="arch" type="xml">
            <xpath expr="//header/button[@id='action_confirm']" position="before">
                <button name="action_noter_relance" string="Noter une relance" type="object"
                        invisible="state not in ('draft', 'sent')"
                        confirm="Ajouter une note de relance dans l'historique du devis ?"
                        confirm-title="Relance du client"
                        confirm-label="Oui, noter"
                        icon="phone"/>
            </xpath>
        </field>
    </record>
</odoo>

Déclare le fichier dans 'data' du manifeste, puis ./odoo-bin -c odoo.conf -d ma_base -u mon_module. Le bouton apparaît sur le devis à l'état Devis, entre « Envoyer » et « Confirmer » :

Trois choix de placement, constatés sur cette vue :

  • //header en position="inside" : le bouton passe en dernier, après « Mettre en devis » et « Rouvrir la facturation ». Simple, mais souvent loin des autres.
  • before / after sur un bouton existant : place précise. Attention, la vue des devis compte deux boutons name="action_confirm" (l'un pour l'état Devis, l'autre pour l'état Envoyé), et un xpath ne retient que le premier trouvé. Vise plutôt par @id quand le bouton en a un, comme ici.
  • Jamais par @string : le libellé est traduit, Odoo refuse ce sélecteur à la validation de la vue. Les mécanismes de l'héritage sont détaillés dans l'article sur l'héritage de vues (lien en fin d'article).

3. Visibilité, droits et confirmation

  • invisible="state not in ('draft', 'sent')" : une expression sur les champs de l'enregistrement. Le bouton disparaît sur une commande confirmée ou annulée.
  • groups="sales_team.group_sale_manager" : le bouton est retiré de la vue des utilisateurs hors groupe. Essai : l'administrateur le voit, l'utilisateur de démonstration Marc Demo (simple vendeur) ne le reçoit pas. Ce n'est pas une sécurité de la méthode elle-même : contrôle les droits dans le Python si l'action est sensible.
  • confirm, confirm-title, confirm-label : une boîte de confirmation avant l'appel, avec son titre et le texte du bouton de validation (cancel-label renomme l'autre bouton, la vue des devis l'emploie sur « Annuler »).

Validée, la boîte appelle la méthode : la notification « Relance notée » s'affiche en haut à droite et la note « Relance téléphonique faite. » arrive en tête de l'historique.

4. L'erreur classique : la méthode privée

Une méthode dont le nom commence par _ (ou décorée @api.private) ne peut pas être appelée depuis le navigateur. Odoo 20 le vérifie dès la validation de la vue : renomme la méthode et le bouton en _noter_relance, lance -u, et le module ne se charge plus :

La même validation refuse un nom de méthode qui n'existe pas sur le modèle (« n'est pas une action valide ») et inscrit un avertissement au journal si la méthode attend des paramètres. Garde le préfixe action_, c'est la convention d'Odoo.

Venant de la 19 : les icônes fa-…

En 19, icon="fa-phone" sur un bouton affichait l'icône FontAwesome. Odoo 20 ne charge plus FontAwesome et passe la valeur telle quelle à sa police d'icônes (Material Symbols) : le bouton s'installe sans erreur, mais l'icône est fausse, ici un tiret parasite devant le combiné. Écris le nom Material, sans préfixe : icon="phone".

À retenir

  • Méthode publique sur _inherit, vue héritée qui vise //header, bouton type="object", puis -u.
  • Ancre le xpath sur un @id ou un @name unique : sur les devis, deux boutons portent action_confirm.
  • Renvoie True pour relire le formulaire ; une notification a besoin de next: soft_reload pour en faire autant.
  • Icônes : noms Material (phone, edit_square…), plus de fa-.
