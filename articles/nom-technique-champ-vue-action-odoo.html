Mode debug Odoo 20 : nom technique d'un champ, d'une vue, d'une action

L'écran dit « Client », ton code attend partner_id. Avant d'écrire un héritage de vue, un domaine ou un env.ref(), il faut le nom technique exact : du champ, de son modèle, de la vue qui l'affiche, de l'action qui ouvre l'écran. Le mode développeur d'Odoo 20 les donne en deux clics, et la console les confirme en une ligne.

~5 minutes de lecture · niveau débutant · parcours Interface web

La réponse en bref

  1. Ajoute ?debug=1 à l'URL (ou Paramètres › Activer le mode développeur).
  2. Champ : survole le ? à côté de son libellé : nom, modèle, type, contexte, domaine.
  3. Vue, action, modèle : bouton insecte de la barre du haut › Afficher : Form, Action, Modèle, Champs ; l'ID externe est sur la fiche ouverte.
  4. Enregistrement : même menu › Métadonnées › « ID XML ».

Vérification : env.ref('module.xmlid') et env['modèle']._fields['champ'] dans odoo-bin shell.

1. Activer le mode développeur

Trois chemins mènent au même mode, à choisir selon l'endroit où tu te trouves :

  • Par l'URL : ajoute ?debug=1 à l'adresse en cours, par exemple /odoo/orders/1?debug=1. Le paramètre est ensuite conservé d'un écran à l'autre.
  • Par les paramètres : Paramètres, bloc Outils développeur › Activer le mode développeur.
  • Par la palette : Ctrl+K, tape exactement debug, puis choisis Activer le mode debug (debug).

Deux signes montrent que c'est actif : un bouton en forme d'insecte apparaît dans la barre du haut, et un petit ? s'affiche à côté de chaque libellé de champ. Pour sortir : ?debug=0, ou l'entrée Quitter le mode débogage en bas du menu de l'insecte.

2. Le nom technique d'un champ : l'infobulle

Ouvre une commande client de la démo (Ventes › Commandes › Commandes, la S00001) et survole le ? à droite de « Client ». En mode développeur, l'infobulle ajoute à l'aide habituelle une fiche technique du champ :

LigneCe que tu en fais
Champ, ModèleLe couple à écrire dans le code : env['sale.order'], order.partner_id, <field name="partner_id"/> dans un héritage de vue.
Type, RelationCe que contient le champ : ici un enregistrement de res.partner, pas un texte.
WidgetLe composant d'affichage choisi par la vue (res_partner_many2one).
Contexte, DomaineCe que la vue passe au champ : ici, le contexte règle la recherche et l'affichage du client (res_partner_search_mode, show_address), le domaine filtre les clients proposés par société. C'est la réponse à « quel contexte a ce champ ? ».
Obligatoire, Lecture seuleLes conditions réelles : le champ passe en lecture seule quand state in ['cancel', 'sale'].

Dans une liste, survole l'en-tête de la colonne. Pour tous les champs du modèle, y compris ceux que la vue n'affiche pas : l'entrée Champs du menu suivant (124 lignes pour sale.order sur cette base).

3. La vue, l'action, l'enregistrement : le menu de l'insecte

Sur la même commande, clique sur l'insecte. Le menu s'adapte à l'écran ouvert ; sur un formulaire, il commence ainsi :

  1. Afficher : Form ouvre la fiche de la vue formulaire affichée : « Nom de vue » sale.order.form, « ID externe » sale.view_order_form. C'est cet ID externe qu'attend le inherit_id d'un héritage de vue. Vue de recherche fait de même pour la barre de recherche, et Arc calculé montre l'architecture telle que le client web l'a reçue, héritages appliqués.
  2. Action ouvre l'action qui a mené à l'écran : « Nom de l'action » Commandes clients, « ID externe » sale.action_orders, « Chemin » orders, « Objet » sale.order.
  3. Métadonnées répond pour l'enregistrement affiché :

« ID » est l'identifiant en base, propre à chaque base. « ID XML » est le nom stable donné par le module qui a créé l'enregistrement : c'est lui qu'il faut écrire dans le code. Un enregistrement créé à la main n'en a pas : get_external_id() renvoie alors une chaîne vide.

Venant de la 19 : la section Sécurité

En 19, la section Sécurité du menu proposait deux entrées, les droits d'accès (ir.model.access) et les règles d'enregistrement (ir.rule). Ces deux modèles n'existent plus en Odoo 20 : il reste une seule entrée, Droits d'accès, qui ouvre les lignes ir.access du modèle. L'infobulle d'un champ related gagne aussi une ligne qui donne le chemin du champ d'origine.

4. Lire l'action dans l'URL

Sans même ouvrir le menu, la barre d'adresse renseigne sur l'action. Une action qui a un « Chemin » s'affiche par ce chemin : Ventes › Commandes › Commandes donne /odoo/orders, et la commande 1, /odoo/orders/1. Une action sans chemin s'affiche par son identifiant : Ventes › Analyse › Ventes donne /odoo/action-446.

Dans l'autre sens, l'URL accepte l'ID externe. Taper /odoo/action-sale.action_order_report_all ouvre l'analyse des ventes, et la barre d'adresse se réécrit en /odoo/action-446. Pratique pour tester un ID externe trouvé dans le code. Si l'ID n'existe pas, le client web retombe sur l'application d'accueil, et le journal du serveur l'écrit :

2026-10-21 11:21:54,972 55815 WARNING ma_base odoo.http: L'action “sale.n_existe_pas” n'existe pas.

5. Vérifier dans odoo-bin shell

Ce que l'écran a donné se confirme dans la console, avant de l'écrire dans un module :

SO = env['sale.order']
f = SO._fields['partner_id']
print(f, f.type, f.comodel_name, f.required, repr(f.string))
print(SO.fields_get(['partner_id'], ['string', 'type', 'relation']))
print([n for n, d in SO.fields_get(attributes=['string']).items() if d['string'] == 'Client'])
action = env.ref('sale.action_orders')
print(action, action.path, action.res_model)
print(env.ref('sale.action_order_report_all').id)
print(env.ref('sale.view_order_form'))
print(SO.browse(1).get_external_id())
  • env.ref('module.id_externe') renvoie l'enregistrement, quel que soit son modèle (action, vue, commande). Un ID externe faux lève ValueError: External ID not found in the system : c'est la vérification.
  • get_external_id() fait le chemin inverse, de l'enregistrement vers son ID XML.
  • _fields['partner_id'] décrit le champ tel que le code le déclare.

Chercher un champ par son libellé français

_fields['partner_id'].string vaut 'Customer' : c'est le libellé source, en anglais, écrit dans le module. Le « Client » de l'écran est sa traduction. Pour retrouver un champ à partir du libellé affiché, passe par fields_get(), qui traduit dans la langue de l'utilisateur : la recherche sur « Client » renvoie bien ['partner_id'], alors que la même recherche sur _fields ne trouverait rien.

À retenir

  • ?debug=1, puis le ? d'un libellé : nom, modèle, type, contexte et domaine du champ, tels que la vue les utilise.
  • Le menu de l'insecte donne la vue (Afficher : Form), l'action, le modèle et la liste des champs ; Métadonnées donne l'ID XML de l'enregistrement.
  • /odoo/<chemin> ou /odoo/action-<id> dans l'URL ; l'URL accepte aussi action-<module.id_externe>.
  • Confirmer avec env.ref(), get_external_id() et fields_get() (libellés traduits) avant d'écrire le code.
