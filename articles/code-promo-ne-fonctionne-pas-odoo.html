Code promo Odoo 20 qui ne fonctionne pas : 8 causes

Le client cite son code, le commercial le saisit sur le devis, et Odoo refuse, ou accepte sans rien déduire. Derrière quelques messages souvent trompeurs se cachent huit causes, toutes reproduites ici sur la base de démonstration, avec leur correction.

~9 minutes de lecture · niveau intermédiaire · série Remises et promotions avec Odoo 20

Édition : Community. Écrit et vérifié sur Odoo 20.0 Community, octobre 2026, sur la base de démonstration (Ventes, Site Web, eCommerce, Point de vente), avec l'option Promotions, Fidélité & Cartes-Cadeaux activée. Les programmes de promotion existent aussi dans l'édition Enterprise.

Avant de commencer

Sur un devis, un code se saisit avec le bouton Code promotionnel, sous les lignes ; une promotion sans code s'applique avec le bouton Récompense. Odoo contrôle alors le programme dans un ordre précis : le code existe-t-il, le programme est-il en vigueur pour ce devis, la condition est-elle remplie, le code a-t-il encore des usages, la récompense a-t-elle bien été ajoutée. Chaque étape a son message, et le même message peut recouvrir plusieurs causes. Pour la prise en main des remises du devis et des listes de prix, voir Listes de prix et remises dans Odoo 20.

Toutes les causes ci-dessous sont reproduites avec un programme d'essai, créé dans Ventes › Promotions › Remise & Fidélité : type Code de remise, nom « Offre mobilier : 15 % dès 500 $ », récompense de 15 % sur la commande et une règle unique.

Le tableau suivant sert de point d'entrée : repérez le message affiché, puis lisez la section correspondante.

Objectifs

À la fin de cet article, vous saurez :

  • relier chaque message d'erreur d'un code promo à sa cause réelle ;
  • vérifier la période, la liste de prix, la condition et la limite d'un programme ;
  • débloquer un devis refusé par l'option « une fois par client » ;
  • repérer une remise oubliée, périmée ou retirée avant de confirmer la commande.

1. Le code est mal saisi

Sur un devis pour Acme Corporation avec une Table extérieure (589 $), cliquez sur Code promotionnel et saisissez mobilier15, en minuscules.

Odoo cherche le code tel quel : la casse compte. MOBILIER15 passe, mobilier15 non. Les espaces avant ou après le code, en revanche, sont ignorés.

Correction : recopiez le code depuis la règle du programme (fenêtre de la figure 1). Pour les codes diffusés au public, préférez des codes en majuscules seules, sans lettres ambiguës. Si le code est correct et le message persiste, passez à la cause 2 : le même message signale un programme inaccessible.

2. Le programme ne vise pas ce devis

Au-dessus des onglets du programme, deux champs restreignent son usage : Pour (des listes de prix) et Availability Dates (une période, bornes incluses). Pour la démonstration, la période est fixée du 1er septembre au 5 octobre, et le code est saisi le 6 octobre.

Le code, pourtant correctement saisi, est refusé avec le même message qu'une faute de frappe :

Odoo ne cherche le code que parmi les programmes en vigueur pour le devis. Sont écartés, avec ce même message :

  • un programme dont la période est terminée ou pas encore commencée (la date du jour est prise dans le fuseau horaire de la société) ;
  • un programme réservé à d'autres listes de prix : avec Pour = USD, le devis d'Azure Interior, client de la liste « Grossiste », est refusé ;
  • un programme d'une autre société ;
  • un programme dont la case Ventes de l'onglet Settings (bloc Disponible sur) est décochée, ou un programme archivé.

Correction : ouvrez le programme et contrôlez ces quatre points ; vérifiez sur le devis la liste de prix et la société. Prolonger la période ou ajouter la liste de prix suffit, le code s'applique aussitôt.

3. La condition n'est pas remplie

Un devis pour Acme Corporation porte dix Boîtes de rangement (158 $) et un Montage de meubles (2 000 $), soit 2 481,70 $ toutes taxes comprises. Le code MOBILIER15 est saisi :

Le devis dépasse largement 500 $, mais le montage est un service hors de la catégorie Mobilier : seules les boîtes comptent, 181,70 $ taxes comprises. Le message, affiché en anglais, dit exactement cela : « au moins 500 USD des produits éligibles ». Odoo 20 a changé ce texte : en Odoo 19, il parlait seulement d'un minimum à acheter.

Deux réglages de la règle font la différence :

  • Parmi (produits, catégories, étiquette) : délimite les articles pris en compte dans le montant et la quantité minimale ;
  • taxes incluses / taxes exclues à côté de l'achat minimum : par défaut, le seuil se compare au montant TTC.

Quand c'est la quantité qui manque, le message devient « Vous n'avez pas les quantités de produit requises sur votre commande client. ».

Correction : c'est le comportement voulu par la règle. Ajoutez des articles éligibles, ou élargissez la règle si l'offre annoncée au client portait sur toute la commande.

4. La limite d'utilisation est atteinte

Cochez Limite d'utilisation et fixez-la à 1. Le programme affiche aussitôt « 1 utilisé(s) », alors qu'aucune commande n'est confirmée : le premier devis d'Acme Corporation, resté en brouillon, porte déjà la remise.

Sur un nouveau devis, pour Wood Corner, le code est refusé :

Le compteur additionne toutes les commandes qui portent une ligne de récompense du programme, quel que soit leur état. Un devis abandonné mais jamais annulé consomme donc un usage. Annuler le devis ou supprimer sa ligne de remise libère l'usage.

Les bons de réduction à usage unique suivent la même logique, avec leurs propres messages : « Ce bon de réduction a déjà été utilisé. » et, après la date de validité du bon, « Ce bon de réduction est expiré. ».

Correction : repérez les devis qui portent la remise (liste des devis, recherche sur le code ou le client), annulez ceux qui sont abandonnés ou supprimez leur ligne de remise ; sinon relevez la limite.

5. Le client a déjà utilisé le code

Odoo 20 ajoute aux programmes de type Code de remise une case Once per user (une fois par client). Le client est mémorisé à la confirmation d'une commande qui porte le code, pas à la saisie. D'où deux situations.

Le cas simple : le client a déjà une commande confirmée avec le code ; une nouvelle saisie affiche « This promo code can only be used once. » dans une fenêtre Erreur de validation.

Le cas déroutant : le code a été saisi sur deux devis du même client, ici Ready Mat, tant qu'aucun n'était confirmé. Les deux portent la remise de 15 %. Le premier se confirme normalement ; le second est bloqué au moment de la confirmation :

Correction : sur le devis bloqué, supprimez la ligne de remise du code (icône corbeille), enregistrez, puis confirmez : la commande passe, sans la remise. Le code reste utilisable par les autres clients.

6. La récompense n'a pas été ajoutée

Un code accepté ne crée pas encore de remise : Odoo ouvre la fenêtre Récompenses disponibles, dans laquelle il faut cocher la récompense, même quand elle est seule. Cliquer directement sur Appliquer donne :

Le piège vient ensuite. Si le commercial ferme cette fenêtre par Annuler, le devis reste sans remise, mais le code y est mémorisé : le bouton Récompense ne propose plus rien, et une remise « une fois par client » peut même bloquer la confirmation (cause 5) sans avoir rien accordé. Ressaisissez le code et cochez la récompense :

Les promotions automatiques posent le même problème sous une autre forme : sur un devis, rien ne s'applique seul. Avec la promotion « 5 % dès 1 500 $ », un devis de trois Tables extérieures (1 767 $) confirmé sans clic sur Récompense devient une commande sans remise. Odoo se contente d'une notification :

Correction : vérifiez qu'une ligne de remise figure sur le devis avant de le confirmer ; cliquez sur Récompense pour les promotions sans code. Quand une seule récompense est disponible, ce bouton l'ajoute directement.

7. Le devis a été modifié après le code

La ligne de remise est calculée au moment où le code est appliqué. Si le commercial modifie ensuite les quantités, elle n'est pas recalculée. Sur un devis pour Gemini Furniture, 40 Boîtes de rangement (632 $) reçoivent 15 %, soit −94,80 $. La quantité passe ensuite à 20 :

Le devis affiche donc une remise fausse, et la condition des 500 $ n'est même plus remplie. À la confirmation, Odoo réévalue les programmes et retire la ligne, sans aucun message :

Correction : après toute modification d'un devis qui porte une promotion, cliquez sur Récompense. Le bouton met à jour les lignes de promotion : sur un devis où la condition n'est plus remplie, il retire la remise ; sur un devis encore éligible, il recalcule le montant. Renvoyez le devis au client après cette mise à jour.

8. Deux remises sur la commande entière

Un devis pour Wood Corner porte déjà la remise MOBILIER15 (15 %). Le commercial saisit aussi le code de démonstration 10pc (10 % sur la commande) :

Odoo n'accorde qu'une remise s'appliquant à toute la commande. Quand la nouvelle est moins avantageuse, elle est refusée avec ce message ; quand elle est plus avantageuse, elle remplace l'ancienne. Les remises de la liste de prix (colonne Rem.%) ne sont pas concernées : elles s'ajoutent au code.

Correction : si le cumul est voulu, dans la récompense de l'un des deux programmes, remplacez l'application sur la Commande par Produits spécifiques ou Produit le moins cher ; sinon, supprimez la ligne de la remise la moins utile.

Points de vigilance

Le message ne nomme pas toujours la cause

« Ce code n'est pas valide » couvre la faute de frappe comme la période terminée ; « Ce code est expiré » désigne la limite d'usages, pas une date. Avant de recréer un programme, ouvrez-le et contrôlez période, listes de prix, limite et règle.

Un devis abandonné garde ses avantages

Un devis en brouillon qui porte une remise consomme un usage de la limite. Annulez les devis perdus plutôt que de les laisser ouverts.

Les programmes de démonstration se mêlent aux essais

Sur la base de démonstration, la livraison gratuite, la fidélité et le bon « prochaine commande » sont actifs : la fenêtre Récompenses disponibles peut proposer d'autres lignes que celle du code testé, et une commande confirmée affiche des points de fidélité. Lisez le nom du programme avant de cocher.

Exercice

Objectif : constater qu'une remise n'est pas recalculée après une modification du devis, puis la mettre à jour.

Indication : sur un devis pour Wood Corner avec deux Tables extérieures, appliquez le code de démonstration 10pc (bouton Code promotionnel, récompense cochée). Passez ensuite la quantité à 1 et enregistrez, puis cliquez sur Récompense.

Critère de réussite : après l'application, la remise vaut −117,80 $ ; elle reste à −117,80 $ après le passage à une table ; elle passe à −58,90 $ après le clic sur Récompense.

À retenir

  • Le code est sensible à la casse ; un programme hors période, hors liste de prix ou d'une autre société donne le même message qu'une faute de frappe.
  • Le montant minimum se calcule sur les seuls articles éligibles, taxes comprises par défaut.
  • La limite d'utilisation compte les devis en brouillon ; « Once per user » mémorise le client à la confirmation et peut bloquer un second devis.
  • Un code accepté ne remise rien tant que la récompense n'est pas cochée ; une promotion automatique attend le bouton Récompense.
  • Après toute modification du devis, Récompense met à jour la remise ; sans cela, la confirmation la corrige ou la retire sans prévenir.
