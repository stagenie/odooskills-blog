Gestionnaire de bases Odoo 20 : Access Denied et mot de passe maître

Créer, sauvegarder ou restaurer une base depuis /web/database/manager et tomber sur un refus : en Odoo 20, la page dit enfin pourquoi. Deux causes seulement, list_db coupé ou mauvais mot de passe maître, et chacune se corrige dans le fichier de configuration.

~5 minutes de lecture · niveau intermédiaire · série Astuces dev Odoo 20

Édition : Community. Vérifié sur Odoo 20.0 Community, octobre 2026, serveur lancé avec son propre fichier de configuration ; mots de passe maîtres de démonstration, base de test créée, sauvegardée puis supprimée par le gestionnaire.

1. Lis la phrase entière, pas seulement « refusé »

Créer, sauvegarder, restaurer, dupliquer ou supprimer : chaque action du gestionnaire vérifie d'abord list_db, ensuite le mot de passe maître. Quand l'une échoue, Odoo 20 réaffiche le gestionnaire avec un bandeau rouge de la forme Could not <action> database. <raison>, et répond avec le statut HTTP 403.

Le serveur écrit la même raison dans son journal, au niveau WARNING :

WARNING ma_base odoo.http: Database management function blocked, bad admin password.

En 19, ces deux refus levaient la même exception sans message : la page disait seulement Database creation error: Access Denied (ou backup, restore…), avec un statut 200. En Odoo 20, la raison distingue les deux cas : functions blocked, admin disabled database listing (au pluriel) pour list_db, function blocked, bad admin password pour le mot de passe.

2. « Disabled by the administrator » : rallumer list_db

L'option list_db (ou --no-database-list en ligne de commande) ne cache pas seulement la liste : elle coupe tout le gestionnaire. La page n'affiche plus aucune base ni aucun bouton, et un formulaire envoyé quand même (un curl sur /web/database/backup, par exemple) est refusé en 403 avec Database management functions blocked, admin disabled database listing. Ce n'est pas le mot de passe : même le bon est refusé.

Cherche l'option dans le fichier de configuration et dans la ligne de commande du service (unité systemd, command: d'un fichier Compose). Sur un serveur de production : passer à list_db = True, redémarrer, faire l'opération, remettre False et redémarrer.

[options]
list_db = True
dbfilter = ^ma_base
admin_passwd = $pbkdf2-sha512$600000$…

Une sauvegarde de routine n'a pas besoin du gestionnaire : odoo-bin db dump fait la même archive en ligne de commande, sans mot de passe maître ni list_db.

3. « Bad admin password » : où vit le mot de passe maître

Le mot de passe maître n'est pas celui de l'utilisateur admin d'une base, ni celui de PostgreSQL : c'est la clé admin_passwd du fichier de configuration du serveur. Elle ne se passe que par ce fichier :

./odoo-bin -c odoo.conf --admin_passwd=Demo-Maitre-20
Usage: odoo-bin [--addons-path=PATH,...] server [options] odoo-bin [--addons-path=PATH,...] server: error: no such option: --admin_passwd

Quand tu le changes par le bouton Set Master Password, Odoo réécrit cette ligne avec une empreinte $pbkdf2-sha512$600000$… : impossible de la relire. Si personne ne connaît plus le mot de passe, la marche à suivre est la même partout :

  1. Ouvre le fichier de configuration du service et remplace la ligne par une valeur en clair : admin_passwd = Nouveau-Maitre-20.
  2. Redémarre le service : la valeur est lue au démarrage seulement.
  3. Fais ton opération avec ce mot de passe.
  4. Repasse par Set Master Password pour que la ligne redevienne une empreinte.

Odoo accepte encore la forme en clair mais la tient pour dépréciée : il ne la convertit pas tout seul dans le fichier. La dernière commande de l'image appelle la route du bouton (/web/database/change_password) ; dans le navigateur, le bouton fait la même chose.

Le fichier doit être modifiable par le compte qui fait tourner Odoo. Sinon, le bouton semble réussir : retour au gestionnaire, aucun bandeau, et le nouveau mot de passe marche… jusqu'au prochain redémarrage. Seule trace, une ligne sur la sortie d'erreur du serveur, ERROR: couldn't write the config file. Au redémarrage, l'ancien mot de passe revient et le nouveau prend un bad admin password.

Sans admin_passwd, le premier mot de passe tapé devient le maître

Si la clé est absente, Odoo 20 prend admin par défaut et affiche Warning, your Odoo database manager is not protected. Dans cet état, la première action envoyée avec un mot de passe, quel qu'il soit, l'enregistre comme mot de passe maître et l'écrit dans le fichier de configuration, même si l'action échoue : une suppression d'une base inexistante a suffi à ajouter la ligne admin_passwd = $pbkdf2-sha512$…. Une faute de frappe à ce moment-là, et le « bon » mot de passe est refusé ensuite. Pose admin_passwd toi-même avant la première ouverture du gestionnaire.

4. La base n'apparaît pas dans la liste

Pas de refus, mais une liste incomplète, voire le formulaire de création à sa place. Trois réglages en décident :

  • dbfilter : seules les bases dont le nom correspond à l'expression sont montrées. Sur le serveur de test, dbfilter = ^ma_base ne laissait voir que ma_base et ma_base_test parmi toutes les bases du PostgreSQL.
  • db_name (option -d) sans dbfilter : Odoo ne consulte plus PostgreSQL et montre seulement les bases nommées là.
  • Le propriétaire : Odoo ne liste que les bases dont le propriétaire est le rôle PostgreSQL de db_user. Une base qui appartient à un autre rôle, même accessible, n'apparaît pas.

À retenir

  • Odoo 20 dit pourquoi : admin disabled database listing = list_db, bad admin password = admin_passwd.
  • admin_passwd se règle seulement dans le fichier de configuration ; oublié, on le réécrit en clair, on redémarre, puis Set Master Password le remet en empreinte.
  • Pose le mot de passe maître avant la première visite : sinon le premier mot de passe tapé le devient.
  • Base absente de la liste : dbfilter, db_name ou propriétaire PostgreSQL.
