Capitaux propres et actionnaires avec Odoo 20

Qui détient quoi, avec combien de voix, et ce que pèse chaque part : l'application Capitaux propres d'Odoo 20 Enterprise tient les classes de titres, les transactions et la table de capitalisation d'une société.

~10 minutes de lecture · niveau intermédiaire

Édition : Enterprise. Écrit et vérifié sur Odoo 20.0 Enterprise (base hébergée sur odoo.com), octobre 2026.

La répartition du capital vit souvent dans un tableur : une ligne par actionnaire, des colonnes qui se décalent à chaque augmentation de capital, des pourcentages recalculés à la main. Odoo 20 Enterprise propose une application dédiée, Capitaux propres, que l'écran Applications décrit ainsi : « Manage securities, transactions, and cap tables ». Chaque mouvement de titres s'y saisit comme une transaction, et la table de capitalisation se déduit des transactions : titres par actionnaire, part du capital, droits de vote, part entièrement diluée et valorisation.

L'application installe ses propres données de démonstration. Les exemples portent sur la société My Company (San Francisco), la plus fournie : trois actionnaires de démonstration, six classes de titres, neuf transactions et quatre valorisations. Une émission d'actions a été ajoutée pour l'article ; tout le reste vient de la démonstration.

Objectifs

À la fin de cet article, vous saurez :

  • installer l'application Capitaux propres et donner accès à ses écrans ;
  • lire la table de capitalisation : propriété, droits de vote, entièrement dilué, valorisation ;
  • définir des classes de titres, actions ou options ;
  • enregistrer une émission et voir la table se recalculer ;
  • situer les valorisations et les bénéficiaires effectifs dans l'application.

Comment l'application s'organise

Le schéma ci-dessous montre d'où vient chaque chiffre de la table de capitalisation, avec le menu où se trouve chaque élément.

Rien ne se saisit directement dans la table de capitalisation : elle additionne les transactions de chaque société, classe par classe. Les valorisations se saisissent à part et fournissent le montant de la dernière colonne. Les bénéficiaires effectifs forment une liste indépendante : leurs pourcentages sont déclarés, pas calculés à partir des transactions.

1. Installer l'application et ouvrir ses écrans

Dans Applications, cherchez Capitaux propres (module equity, rangé dans la catégorie Facturation) et cliquez sur Activer. L'application ne dépend que du module Portail : sur la base de démonstration, son installation n'a rien ajouté d'autre.

L'accès passe par deux groupes, Capitaux propres / Visionneur et Capitaux propres / Manager. L'utilisateur qui installe l'application reçoit le rôle Manager ; un autre administrateur de la base n'a pas accès aux données de l'application tant que l'un de ces rôles ne figure pas sur sa fiche (Paramètres › Utilisateurs). Pour l'article, le compte utilisé a reçu le rôle Manager.

Le menu de l'application compte quatre entrées : Tableau de bord, Propriété (Transactions, Valorisations, UBO), Analyse (Table de capitalisation, Table de capitalisation (tableau croisé), Valorisation) et Configuration (Classes de titres). Le tableau de bord affiche une carte par société suivie.

Chaque carte donne le nombre d'actionnaires et de transactions et la dernière valorisation, avec sa courbe. La démonstration suit trois sociétés : My Company (San Francisco), mais aussi Azure Interior et Acme Corporation, deux clients de la démo. Le champ Société d'une transaction désigne en effet un contact, et non une société de la base : l'application peut donc décrire aussi le capital d'une filiale ou d'une participation qui n'a pas sa propre comptabilité dans Odoo. La carte d'Acme Corporation affiche 0 $ : aucune valorisation n'est saisie pour elle.

2. Lire la table de capitalisation

Ouvrez Analyse › Table de capitalisation. L'écran présente un bloc par société : une colonne par classe de titres, le total, puis cinq indicateurs. La ligne Securities donne les totaux de la société ; viennent ensuite une ligne par actionnaire et, s'il y a lieu, une ligne Non assigné pour les titres émis sans titulaire.

Pour tester l'application sur votre propre base, une base d'essai se crée depuis le site d'Odoo ; les données de démonstration de Capitaux propres y donnent la même table.

3. Définir les classes de titres

Les colonnes de la table viennent de Configuration › Classes de titres. Une classe porte un nom, un type, Partages (des actions) ou Options, un nombre de voix par action et une case Distribution des dividendes.

La démonstration en compte six. ORD, Seed et Class B donnent une voix par action, Class A en donne deux ; les quatre distribuent un dividende. Les deux réserves d'options, Option Pool 1 et Option pool 2, ne donnent ni voix ni dividende. Les classes sont communes à toutes les sociétés suivies ; la poignée à gauche de chaque ligne règle leur ordre, celui que reprennent les colonnes de la table. La classe Seed n'a encore servi à aucune transaction : elle n'apparaît pas dans la table de la figure 3.

4. Les quatre types de transactions

Propriété › Transactions liste tous les mouvements de titres, toutes sociétés confondues : date, société, abonné (le bénéficiaire), type, nombre de titres, classe, prix par titre et total.

Ces lignes suffisent à refaire la table de la figure 3 :

  • Émission : la société crée des titres pour un abonné. Joel Willis reçoit 300 ORD, Josefine Dubois 10 Class A ; l'émission de 120 Option pool 2 sans abonné donne la ligne Non assigné.
  • Annulation : des titres disparaissent. 290 des 300 ORD de Joel Willis sont annulés, d'où le total de 10 ORD.
  • Transfert : des titres passent d'un vendeur à un acheteur, sans changer le total. Joel Willis cède 5 ORD à Josefine Dubois, qui lui cède 2 Class A.
  • Exercice d'option : des options deviennent des actions d'une autre classe.

Le formulaire change selon le type choisi. Pour un exercice d'option, il demande la classe d'origine et la classe d'arrivée.

Joel Willis exerce 80 de ses 500 options Option Pool 1 au prix de 13,00 $ : il lui reste 420 options et il gagne 80 actions Class B, exactement ce que montre sa ligne dans la table. La zone Notes suggère d'y consigner la période d'acquisition ou la date limite d'exercice : l'application n'en tire aucun calcul. Pour un transfert, le formulaire demande un Vendeur et un Acheteur au lieu de l'abonné.

5. Enregistrer une émission d'actions

Pour l'article, My Company (San Francisco) émet 20 actions Seed au profit de Josefine Dubois, à 25,00 $ l'action. Depuis Propriété › Transactions, bouton Nouveau (ou Nouvelle transaction dans la table de capitalisation) :

  1. Laissez le type Émission, sélectionné d'office.
  2. Dans Société, choisissez My Company (San Francisco) dans la liste proposée.
  3. Gardez la Date du jour et choisissez l'Abonné, Josefine Dubois.
  4. Saisissez 20 dans # Titres et choisissez la classe Seed à droite du nombre.
  5. Saisissez le Prix, 25,00 par titre financier, en USD : le Total passe à 500,00 $.
  6. Enregistrez (icône de nuage).

Le nom de la transaction résume la saisie : « Émission 20.00 Seed ». Le bandeau Documents justificatifs manquants ! reste affiché tant qu'aucune pièce n'est jointe ; le bouton Uploader des fichiers ou la discussion permettent d'en ajouter une. La transaction n'a pas d'état à confirmer : elle compte dans la table dès son enregistrement.

La colonne Seed apparaît, le total passe de 740 à 760 titres et de 100 à 120 actions. Josefine Dubois passe à 33 actions, soit 27,5 % du capital et 31,54 % des voix (41 voix sur 130) ; Joel Willis, sans rien avoir cédé, descend à 72,5 % : c'est la dilution, visible ligne par ligne. La valorisation de la société, elle, reste à 3 000,00 $ : le prix de 25,00 $ payé pour les actions Seed ne crée pas de valorisation. Seule la répartition des 3 000,00 $ change (130,26 $ pour Josefine Dubois, soit 4,34 % de 3 000,00 $).

6. Valorisations et bénéficiaires effectifs

Le montant de la colonne Valorisation vient de Propriété › Valorisations. Une valorisation porte une date, une société, un événement, Audit ou Transaction, un prix par action et un nombre d'actions ; le bouton Nouvelle valorisation d'une transaction ouvre aussi un formulaire de valorisation. La démonstration en contient six, dont quatre pour My Company (San Francisco) : la plus récente, un audit du 29 août à 3 000,00 $, est celle qu'utilise la table. Analyse › Valorisation les trace dans le temps.

Chaque courbe reprend, mois par mois, la dernière valorisation connue de la société. Acme Corporation n'y figure pas, faute de valorisation.

Le menu Propriété › UBO ouvre la liste des Bénéficiaires effectifs, regroupée par société. Chaque ligne nomme un titulaire, une méthode de contrôle, une part de propriété et de droits de vote, et une date de début de contrôle (et, si besoin, de fin).

La liste des méthodes de contrôle distingue les sociétés (catégorie 1, détention de capital ou de droits de vote ; catégorie 2, contrôle par d'autres moyens ; catégorie 3, dirigeant exécutif) et les ONG (six catégories). Un rôle peut s'y ajouter, par exemple Président du conseil d'administration ou Secrétaire. Ces pourcentages sont saisis : ils ne sont pas tirés des transactions. Pour Azure Interior, la table de capitalisation montre 100 Class B détenues par Ready Mat, Julie Richards, tandis que la liste des bénéficiaires effectifs déclare 35 % et 30 % pour deux contacts d'Azure Interior : les deux écrans se tiennent à jour chacun de leur côté. L'application conserve ces déclarations et leurs pièces jointes ; elle ne dit rien de leur valeur légale, qui dépend du droit de chaque pays.

Et en Community ?

Le capital au bilan, pas les actionnaires

Le module equity ne fait pas partie d'Odoo 20 Community : pas de classes de titres, pas de transactions sur titres, pas de table de capitalisation. La comptabilité Community classe bien les comptes de capital dans le type « Capitaux propres » du plan comptable, ce qui donne le montant du capital au bilan, mais pas sa répartition entre actionnaires ; celle-ci reste à tenir hors d'Odoo. La lecture du bilan dans l'Enterprise est présentée dans Bilan, compte de résultat et TVA avec Odoo 20.

Pour un groupe de plusieurs sociétés, la création des sociétés et la bascule de l'une à l'autre sont décrites dans Multi-société dans Odoo 19 Community, un article écrit pour Odoo 19 dont la démarche reste valable.

Points de vigilance

Choisir la société dans la liste, pas la créer

Le champ Société propose, sous les contacts existants, une ligne « Créer » portant le texte tapé. La choisir par erreur crée un nouveau contact du même nom, et la transaction ouvre alors un second bloc dans la table de capitalisation. Vérifiez qu'un seul bloc porte le nom de la société après chaque saisie.

Une transaction ne revalorise pas la société

Le prix d'une émission ou d'un transfert ne change pas la colonne Valorisation : elle suit la dernière valorisation saisie. Après une levée de fonds, enregistrez la nouvelle valorisation avec le bouton Nouvelle valorisation.

Les droits d'accès ne suivent pas le rôle d'administrateur

Seul l'utilisateur qui installe l'application reçoit le rôle Manager. Les autres, administrateurs compris, doivent recevoir Capitaux propres / Visionneur ou Manager sur leur fiche.

Envoyer écrit à l'actionnaire

Le bouton Envoyer de la table ou d'une transaction prépare un courriel à l'actionnaire. Sur la démonstration, depuis la transaction de Josefine Dubois, le champ Destinataires est prérempli avec l'abonné ; depuis la table, il s'est ouvert vide. Relisez-le avant d'envoyer, surtout sur une base qui contient de vraies adresses.

Exercice

Objectif : enregistrer une cession entre actionnaires.

Indication : créez une transaction de type Transfert pour My Company (San Francisco) : vendeur Josefine Dubois, acheteur Joel Willis, 5 titres de la classe Seed, puis ouvrez Analyse › Table de capitalisation.

Critère de réussite : la colonne Seed affiche 15 pour Josefine Dubois et 5 pour Joel Willis, et le total de la société reste à 760 titres.

À retenir

  • Capitaux propres (Enterprise) tient, pour chaque société suivie, des classes de titres, des transactions et une table de capitalisation calculée.
  • Quatre types de transactions : Émission, Transfert, Exercice d'option, Annulation.
  • Propriété compte les actions, Droits de vote les voix par action, Entièrement dilué tous les titres, options comprises.
  • La colonne Valorisation répartit la dernière valorisation saisie ; une transaction ne la modifie pas.
  • Les bénéficiaires effectifs sont déclarés à part, avec leur méthode de contrôle.
