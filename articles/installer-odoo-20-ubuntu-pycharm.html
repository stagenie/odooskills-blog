Installer Odoo 20 sur Ubuntu et le lancer dans PyCharm

Un poste de développement Odoo 20 tient dans un seul dossier : les sources, un environnement Python, un fichier de configuration et un dossier pour tes modules. On le monte de zéro sur Ubuntu 24.04, on crée une première base, puis on lance et on débogue le serveur depuis PyCharm. Chaque commande a été rejouée dans un dossier neuf.

~14 minutes de lecture · niveau débutant · parcours Fondamentaux

Ce que tu vas apprendre

L'installation

Paquets système, rôle PostgreSQL, sources en branche 20.0 et environnement virtuel Python 3.12.

La configuration

Un odoo.conf de développement : chemins des modules, rechargement automatique, port.

L'IDE

Le bon interpréteur dans PyCharm, une configuration d'exécution et un premier point d'arrêt.

Prérequis

  • Ubuntu 24.04 LTS (poste ou machine virtuelle), avec un compte qui peut utiliser sudo. Cette version fournit Python 3.12.3 et PostgreSQL 16 : ce sont exactement les minimums d'Odoo 20.
  • Environ 2 Go d'espace disque : 1,4 Go pour les sources, un peu plus de 200 Mo pour l'environnement Python.
  • PyCharm, édition gratuite ou Professional (l'étape 8 fonctionne avec les deux).
  • Une connexion Internet pour git et pip.

Ce que tu vas construire

Tout vit dans ~/odoo20. Rien n'est installé dans le Python du système : on peut supprimer le dossier et la base, et le poste redevient comme avant.

Ce dossier servira pendant toute la série : c'est dans custom-addons/ que se construira, article après article, le module Bibliothèque (livres, exemplaires, adhérents, emprunts).

1. Les paquets système

Une seule commande installe Git, l'outil venv, PostgreSQL et ce qu'il faut pour compiler les dépendances Python écrites en C :

sudo apt update
sudo apt install -y git python3-venv python3-dev build-essential \
    libpq-dev libldap2-dev libsasl2-dev postgresql
PaquetPourquoi
postgresqlSur Ubuntu 24.04, ce paquet installe PostgreSQL 16, le minimum exigé par Odoo 20.
python3-venvCréer l'environnement virtuel de l'étape 4.
build-essential, python3-devCompiler les dépendances Python qui contiennent du C.
libpq-devEn-têtes PostgreSQL, pour compiler psycopg2 (le pilote de base de données).
libldap2-dev, libsasl2-devPour compiler python-ldap, présent dans la liste des dépendances d'Odoo.

Sans ces trois bibliothèques de développement, pip install s'arrête à l'étape 4 sur une erreur de compilation.

2. Un rôle PostgreSQL à ton nom

Odoo refuse de démarrer avec l'utilisateur postgres (« Using the database user 'postgres' is a security risk, aborting. »). On crée donc un rôle qui porte le nom de ton compte Linux, avec le seul droit de créer des bases :

sudo -u postgres createuser --createdb --no-superuser --no-createrole $USER

Comme le rôle a le même nom que ton compte, PostgreSQL te reconnaît par la connexion locale sans mot de passe. C'est pour cela que le fichier de configuration de l'étape 5 ne contient ni utilisateur ni mot de passe de base.

PostgreSQL déjà installé pour une autre version d'Odoo ?

Si ton poste fait déjà tourner un PostgreSQL plus ancien (le 14 pour Odoo 16 à 19, par exemple), le 16 s'installe à côté sur un autre port, en général 5433. Vérifie avec pg_lsclusters, ajoute -p 5433 à la commande createuser et db_port = 5433 dans odoo.conf. C'est la configuration utilisée pour les captures de cet article.

3. Les sources d'Odoo 20

mkdir ~/odoo20 && cd ~/odoo20
git clone --depth 1 --branch 20.0 https://github.com/odoo/odoo.git odoo

--depth 1 ne télécharge que le dernier état de la branche, pas tout l'historique : le clonage prend une à deux minutes selon la connexion et le dossier odoo/ pèse 1,4 Go. Pour récupérer plus tard les correctifs publiés sur la branche, un git pull dans odoo/ suffit.

4. L'environnement Python

python3 -m venv .venv
.venv/bin/pip install --upgrade pip wheel
.venv/bin/pip install -r odoo/requirements.txt
.venv/bin/pip install inotify phonenumbers

L'environnement s'appelle .venv, avec un point : c'est le nom que PyCharm cherche en premier quand il ouvre un dossier. Toutes les commandes passent par .venv/bin/…, donc inutile de l'activer. L'installation des dépendances prend une à deux minutes selon la connexion.

Pourquoi installer inotify et phonenumbers à part

inotify ne figure pas dans requirements.txt. Sans lui, l'option de rechargement automatique de l'étape 5 est coupée, et Odoo ne le signale que par une ligne dans le journal :

WARNING ? odoo.service.server: 'inotify' module not installed. Code autoreload feature is disabled

Tu modifierais alors ton code Python sans que le serveur redémarre.

phonenumbers non plus ne figure pas dans requirements.txt. Pour une société française (et une vingtaine d'autres pays européens), toute application qui installe la comptabilité (Ventes, Facturation, Achats…) ajoute le module de facturation électronique account_peppol, qui l'exige. Sans elle, l'activation s'arrête sur « Opération invalide » : dépendance externe non trouvée : phonenumbers. La commande apt install proposée par ce message vise le Python du système, pas .venv.

5. Le fichier odoo.conf

Crée le dossier de tes modules, puis le fichier de configuration à la racine du projet :

mkdir custom-addons
cat > odoo.conf <<EOF
[options]
addons_path = $HOME/odoo20/odoo/addons,$HOME/odoo20/custom-addons
data_dir = $HOME/odoo20/data
http_port = 8069
dev_mode = reload,xml
log_level = info
EOF

La commande remplace $HOME par ton vrai dossier personnel : le fichier contient des chemins absolus.

OptionRôle
addons_pathOù Odoo cherche les modules : ceux d'Odoo, puis les tiens. Le dossier des modules du noyau (odoo/odoo/addons, qui contient base) est ajouté automatiquement.
data_dirFichiers des pièces jointes et sessions. Le garder dans le projet évite de le chercher dans ~/.local/share.
http_portLe port du navigateur. 8069 est la valeur par défaut, écrite ici pour être visible.
dev_mode = reload,xmlreload redémarre le serveur quand un fichier Python change ; xml relit les vues depuis les fichiers sans mise à jour du module.

Aucune option de base de données : Odoo se connecte au PostgreSQL local, port par défaut, avec ton compte. (Si ton PostgreSQL 16 est sur le 5433, ajoute db_port = 5433.) Le mode xml ne vaut que pour les vues que tu n'as pas modifiées depuis l'interface.

6. Premier lancement en ligne de commande

.venv/bin/python odoo/odoo-bin -c odoo.conf

Le journal tient en une douzaine de lignes (chemins raccourcis en ~) :

WARNING ? odoo.tools.config: option addons_path, invalid addons directory '~/odoo20/custom-addons', skipped INFO ? odoo: Odoo version 20.0 INFO ? odoo: Using configuration file at ~/odoo20/odoo.conf INFO ? odoo: addons paths: _NamespacePath(['~/odoo20/odoo/odoo/addons', '~/odoo20/data/addons/20.0', '~/odoo20/odoo/addons']) INFO ? odoo: database: default@default:5433 INFO ? odoo.service.server: Watching addons folder ~/odoo20/odoo/odoo/addons INFO ? odoo.service.server: AutoReload watcher running with inotify INFO ? odoo.service.server: HTTP service running on 127.0.0.1:8069 INFO ? odoo.service.server.ThreadedServer.cron0: Alive INFO ? odoo.service.server.ThreadedServer.cron1: Alive

Quatre lignes à lire :

  • WARNING … invalid addons directory : normal. Odoo ignore un dossier de modules vide. L'avertissement disparaît dès que custom-addons/ contient un premier module.
  • database: default@default:5433 : « default » veut dire « valeur par défaut de PostgreSQL ». Avec PostgreSQL 16 sur son port standard, la ligne se termine par :default.
  • AutoReload watcher running with inotify : le rechargement automatique est actif. Si tu lis à la place 'inotify' module not installed, reviens à l'étape 4.
  • HTTP service running on 127.0.0.1:8069 : Odoo 20 n'écoute que sur la machine elle-même par défaut. Le navigateur du poste y accède ; un autre ordinateur du réseau, non.

7. La première base : biblio

Ouvre http://localhost:8069. Aucune base n'existe encore : Odoo affiche directement le formulaire de création.

ChampValeurRemarque
Master Passwordcelui proposéNote-le : il sera demandé pour supprimer, sauvegarder ou restaurer une base.
Database NamebiblioLa base du fil rouge de la série.
Email / Passwordadmin / adminAcceptable sur un poste de développement, jamais sur un serveur.
Language / CountryFrench / FranceInterface en français dès la connexion.
Demo DatadécochéLe module Bibliothèque apportera ses propres données.

La création prend une dizaine de secondes, puis Odoo ouvre l'écran des applications.

Le mot de passe maître n'est pas seulement affiché : Odoo l'a écrit haché dans ton fichier de configuration. Vérifie :

grep admin_passwd odoo.conf
admin_passwd = $pbkdf2-sha512$600000$GUOIsRai9P4f43y…

Le fichier odoo.conf contient donc maintenant un secret : ne le copie pas tel quel dans un dépôt Git.

8. Ouvrir le projet dans PyCharm

Arrête d'abord le serveur du terminal (Ctrl+C) : PyCharm va lancer le sien sur le même port. Si tu l'oublies, le second serveur s'arrête aussitôt sur :

OSError: [Errno 98] Address already in use (while attempting to bind on address ('127.0.0.1', 8069))

8.1 Ouvrir le dossier et choisir l'interpréteur

  1. File → Open…, choisis ~/odoo20 (le dossier parent, pas odoo/).
  2. Settings → Python → Interpreter → Add Interpreter → Add Local Interpreter.
  3. Type Virtualenv, option Select existing, chemin ~/odoo20/.venv/bin/python.
  4. La liste des paquets doit afficher babel, inotify, psycopg2… Si elle ne montre que pip, ce n'est pas le bon interpréteur.

Le piège : « Generate new »

Si PyCharm te propose de créer un environnement et que tu acceptes, il fabrique un environnement vide à côté du tien. Le serveur démarre alors sur :

ModuleNotFoundError: No module named 'babel'

Le nom du module manquant peut changer ; la cause est toujours la même : un interpréteur sans les dépendances d'Odoo. Reviens au point 3 et choisis Select existing.

Pour que PyCharm complète from odoo import models, fields dans tes modules : clic droit sur le dossier odoo → Mark Directory as → Sources Root. Tu peux aussi marquer data comme Excluded, pour qu'il ne soit pas indexé.

8.2 La configuration d'exécution

Run → Edit Configurations… → + → Python, puis remplis :

ChampValeur
Nameodoo-20
Interpreter~/odoo20/.venv (Python 3.12)
script~/odoo20/odoo/odoo-bin
Script parameters-c odoo.conf
Working directory~/odoo20
Environment variablesPYTHONUNBUFFERED=1 (le journal s'affiche au fil de l'eau)

Comme odoo.conf est donné en chemin relatif, le Working directory doit être la racine du projet. Coche Store as project file si tu veux retrouver la configuration dans un autre clone. Clique Run : la console affiche le même journal qu'à l'étape 6, jusqu'à HTTP service running on 127.0.0.1:8069.

9. Un premier point d'arrêt

Le meilleur endroit pour vérifier le débogueur est le code qui s'exécute à chaque connexion. Ouvre odoo/addons/web/controllers/home.py et va dans la méthode web_login, sur la ligne :

auth_info = authenticate(request.session, request.env, credential)
  1. Clique dans la marge à gauche de la ligne : un point rouge apparaît.
  2. Lance la configuration avec l'icône Debug (l'insecte) au lieu de Run.
  3. Dans le navigateur, déconnecte-toi puis reconnecte-toi avec admin / admin.
  4. Le navigateur reste en attente et PyCharm s'arrête sur la ligne. Le panneau Threads & Variables montre credential, le dictionnaire construit à partir du formulaire : {'login': 'admin', 'password': 'admin', 'type': 'password'}. À gauche, la pile d'appels remonte de web_login jusqu'au fil du serveur HTTP.
  5. Resume (F9) : la connexion se termine.

Retire ensuite le point d'arrêt : il bloquerait chaque connexion. Tu sais maintenant arrêter Odoo n'importe où, y compris dans son propre code, pour lire l'état réel au lieu de le deviner.

Remarque : le mot de passe saisi apparaît en clair dans le débogueur. C'est normal à cet endroit du code, et c'est une raison de plus pour ne jamais déboguer avec les identifiants d'une base réelle.

Le rechargement automatique, vérifié

Modifie et enregistre n'importe quel fichier .py d'un module présent dans l'addons_path. Une seconde plus tard, la console affiche :

INFO ? odoo.service.server: autoreload: python code updated, autoreload activated INFO ? odoo: Odoo version 20.0

Le serveur a redémarré tout seul, sans que tu touches à PyCharm.

Pense-bête des commandes

Toutes se lancent depuis ~/odoo20. Dans PyCharm, les options s'ajoutent au champ Script parameters.

# Démarrer le serveur
.venv/bin/python odoo/odoo-bin -c odoo.conf

# Ouvrir directement la base biblio
.venv/bin/python odoo/odoo-bin -c odoo.conf -d biblio

# Installer (-i) ou mettre à jour (-u) un module, puis s'arrêter
.venv/bin/python odoo/odoo-bin -c odoo.conf -d biblio -u nom_du_module --stop-after-init

# Mettre à jour les sources d'Odoo 20
git -C odoo pull

Récapitulatif

  • Ubuntu 24.04 fournit Python 3.12 et PostgreSQL 16 : les minimums d'Odoo 20, sans dépôt externe.
  • Un rôle PostgreSQL au nom de ton compte, avec --createdb seulement : pas de mot de passe de base dans la configuration.
  • Sources en --depth 1 --branch 20.0, dépendances dans .venv, et inotify et phonenumbers à ajouter à la main.
  • dev_mode = reload,xml : redémarrage sur modification Python, vues relues depuis les fichiers.
  • Le mot de passe maître proposé à la création de la base est écrit haché dans odoo.conf.
  • Dans PyCharm : Select existing → .venv/bin/python, script odoo/odoo-bin, paramètres -c odoo.conf, répertoire de travail = racine du projet.

La suite de la série crée le premier modèle du module Bibliothèque dans custom-addons/.
