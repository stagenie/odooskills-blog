Le rapport PDF en Odoo 20 : la fiche de prêt

Quand l'exemplaire quitte le comptoir, l'adhérent repart avec une fiche : le livre, la date de retour, une ligne pour signer. Dans Odoo, ce papier est un rapport PDF produit par QWeb : une action d'impression, un gabarit HTML, et un moteur qui le convertit en PDF — moteur qui, en Odoo 20, n'est plus dans le cœur mais dans un module à part.

~13 minutes de lecture · niveau intermédiaire · parcours Framework & ORM

Ce que tu vas apprendre

Déclarer

Une action ir.actions.report rangée dans le menu d'impression, avec un nom de fichier calculé.

Mettre en page

Un gabarit QWeb habillé par la mise en page de la société, écrit en t-out et t-field.

Produire

Le moteur PDF d'Odoo 20, son état, et la version HTML du rapport pour déboguer.

Prérequis

  • Le module biblio des articles précédents : emprunts numérotés, adhérents avec numéro de carte, échéance calculée, groupes « Accueil » et « Bibliothécaire » (voir les droits d'accès).
  • Le binaire wkhtmltopdf sur le serveur (au moins 0.12.0, seuil vérifié par Odoo ; les exemples ont tourné en 0.12.5 à Qt patché) : wkhtmltopdf --version doit répondre.
  • Le serveur Odoo 20 joignable sur http://localhost:8069, base biblio.

1. Trois pièces pour une feuille

Un rapport imprimable n'est pas un type de vue. C'est un assemblage de trois éléments qui se passent le relais :

PièceRôleOù
L'action ir.actions.reportdit quel modèle on imprime, avec quel gabarit, sous quel nom de fichierdonnée XML du module
Le gabarit QWebproduit le HTML de la page, enregistrement par enregistrementdonnée XML du module
Le moteur PDFconvertit ce HTML en PDF paginé, en-tête et pied de page comprisbinaire sur le serveur, piloté par un module Odoo

Le chemin d'un clic : le bouton appelle l'action ; le client web demande le fichier au serveur ; le serveur rend le gabarit en HTML pour les enregistrements choisis, passe ce HTML au moteur, et renvoie le PDF au navigateur. On range les deux fichiers XML dans un dossier report/ du module :

biblio/
├── report/
│   ├── library_loan_report.xml      # l'action
│   └── library_loan_templates.xml   # le gabarit
└── __manifest__.py
    'data': [
        # ... sécurité, séquence, tâche, modèle de courriel
        'report/library_loan_report.xml',
        'report/library_loan_templates.xml',
        'views/library_book_views.xml',
        # ...
    ],

L'ordre compte peu entre les deux : le gabarit est désigné par son nom technique, résolu au moment de l'impression. Il faut en revanche charger l'action avant la vue qui la cite, si une vue y fait référence par %(...)d.

2. L'action d'impression

<record id="action_report_library_loan" model="ir.actions.report">
    <field name="name">Fiche de prêt</field>
    <field name="model">library.loan</field>
    <field name="report_type">qweb-pdf</field>
    <field name="report_name">biblio.report_library_loan</field>
    <field name="print_report_name">'Fiche de prêt - %s' % object.reference</field>
    <field name="binding_model_id" ref="model_library_loan"/>
    <field name="binding_type">report</field>
</record>
  • report_type : qweb-pdf pour un PDF, qweb-html pour afficher la page dans le navigateur. On verra au §6 la forme qweb-pdf-<moteur> qu'ajoute Odoo 20.
  • report_name : le nom technique du gabarit, préfixé par le module (biblio.report_library_loan).
  • print_report_name : une expression Python évaluée avec l'enregistrement dans object (et un module time restreint). Elle ne sert que si un seul enregistrement est imprimé ; pour plusieurs, le fichier prend le nom de l'action.
  • binding_model_id et binding_type="report" : exactement le mécanisme de l'assistant de l'article précédent, mais l'entrée va dans la partie impression du menu Actions, avec une icône d'imprimante.

Pour avoir aussi un bouton visible dans la barre du formulaire, une méthode d'une ligne renvoie l'action :

    def action_print_loan(self):
        return self.env.ref('biblio.action_report_library_loan').report_action(self)
<button name="action_print_loan" type="object" string="Imprimer la fiche"/>

3. Le gabarit QWeb

Deux gabarits, selon l'usage d'Odoo : un document qui dessine une fiche, et une enveloppe qui boucle sur les enregistrements reçus (docs) et appelle le document pour chacun. C'est l'enveloppe que nomme report_name.

<template id="report_library_loan">
    <t t-call="web.html_container">
        <t t-foreach="docs" t-as="o">
            <t t-call="biblio.report_library_loan_document" o="o"/>
        </t>
    </t>
</template>

web.html_container pose la page HTML nue et ses feuilles de style de rapport. Le document, lui, s'habille de la mise en page de la société — logo, adresse, pied de page, numéro de page — en appelant web.external_layout :

<template id="report_library_loan_document">
    <t t-set="address">
        <div t-field="o.member_id.partner_id"
             t-options='{"widget": "contact", "fields": ["name", "address"], "no_marker": True}'/>
    </t>
    <t t-call="web.external_layout" o="o" address="address">
        <div class="page">
            <h2>Fiche de prêt <span t-field="o.reference"/></h2>
            <p>Carte d'adhérent : <strong t-out="o.member_id.card_number"/></p>
            <table class="table table-sm mt-4">
                <thead>
                    <tr><th>Exemplaire</th><th>Livre</th><th>Auteur</th></tr>
                </thead>
                <tbody>
                    <tr>
                        <td t-out="o.copy_id.name"/>
                        <td t-out="o.copy_id.book_id.title"/>
                        <td t-out="o.copy_id.book_id.author_id.name or '-'"/>
                    </tr>
                </tbody>
            </table>
            <div class="row mt-4">
                <div class="col-6">
                    <p class="mb-1">Emprunté le : <strong t-field="o.date_out"/></p>
                    <p class="mb-1">Durée : <strong t-out="o.duration"/> jours</p>
                </div>
                <div class="col-6">
                    <p class="mb-1">À rendre le : <strong t-field="o.date_due"/></p>
                    <p t-if="o.state == 'returned'" class="mb-1">Rendu le : <strong t-field="o.date_return"/></p>
                    <p t-if="o.is_late" class="mb-1 text-danger">En retard de <strong t-out="o.days_late"/> jours</p>
                </div>
            </div>
            <p class="mt-5">Signature de l'adhérent :</p>
        </div>
    </t>
</template>

Trois façons d'écrire une valeur, trois usages :

  • t-field passe par le widget du champ : une date sort au format de la langue (18/09/2026 en français), un contact avec les t-options voulues.
  • t-out écrit la valeur brute, échappée : un texte, un nombre, une expression (author_id.name or '-').
  • t-if n'affiche la ligne « Rendu le » que pour un emprunt rendu, et le retard seulement s'il y en a un — is_late et days_late sont les champs calculés de l'article sur les retards.

⚠️ t-esc n'écrit plus rien en Odoo 20

Un gabarit de rapport recopié d'une version plus ancienne utilise souvent t-esc. En Odoo 20, la directive n'est plus reconnue : pas d'erreur, pas de valeur. Rendu du même petit gabarit en console :

<p>A<span t-esc="x"/>B<span t-out="x"/>C</p>   avec x = 'VAL'
→ <p>A<span></span>B<span>VAL</span>C</p>

WARNING ... ir_qweb: Unknown directives or unused attributes: {'t-esc'} from <span t-esc="x"/>

La fiche sortirait avec des cases vides, et seul le journal du serveur le signale. Remplacer t-esc (et t-raw) par t-out partout ; c'est déjà ce que faisait le corps du modèle de courriel de la relance.

Venant de la 19 : l'adresse passe en attribut

Beaucoup de rapports posaient <t t-set="address"> à l'intérieur du t-call="web.external_layout". En Odoo 20, une variable posée dans le corps d'un t-call n'arrive plus au gabarit appelé : l'adresse disparaît, sans message. D'où la forme ci-dessus : le bloc est construit avant l'appel, puis transmis en attribut (address="address"), comme l'enregistrement (o="o").

4. Premier clic : la mise en page de la société

Sur une base neuve, le premier administrateur qui imprime ne reçoit pas de PDF mais une fenêtre. report_action() vérifie si la société a choisi une mise en page (external_report_layout_id) ; tant que ce champ est vide, elle renvoie l'action du configurateur à la place de l'impression :

if self.env.is_admin() and not self.env.company.external_report_layout_id and config and not discard_logo_check:
    return self._action_configure_external_report_layout(report_action)

« Continuer » enregistre les choix sur la société et lance l'impression demandée ; les clics suivants vont droit au PDF. Un utilisateur non administrateur, lui, n'est jamais arrêté : il imprime avec la mise en page standard (web.external_layout_standard, repli prévu par external_layout). Ce comportement n'a pas changé depuis la 19 — mais le contenu de la fenêtre, si.

Venant de la 19 : Rayé, Encadré et Gras sont devenus des styles de tableau

En 19, Striped, Boxed et Bold étaient des agencements complets, au même rang que Bubble ou Wave, et un réglage de fond de page (layout_background) les accompagnait. En Odoo 20, la ligne « Agencement » propose Light, Bubble, Wave, Folder, Center, Dual, Lines et Compact ; les trois anciens noms sont passés dans une nouvelle ligne « Tableaux », champ report_tables_id de la société (Clair, Encadré, Gras, Rayé, Bulle, Colonne, Compact), qui ne change que le dessin des tableaux. layout_background n'existe plus. Un module qui forçait web.external_layout_striped doit être revu.

5. La fiche imprimée

Le navigateur télécharge Fiche de prêt - EMP_2026_0009.pdf : l'expression de print_report_name a donné Fiche de prêt - EMP/2026/0009, et le navigateur a remplacé les barres obliques, interdites dans un nom de fichier. La page, convertie en image (le milieu, vide, est coupé) :

Ce que la mise en page a ajouté seule : le nom de la société en tête, le courriel en pied, le « Page 1 / 1 ». L'adresse de l'adhérent est à l'emplacement prévu pour le destinataire, parce que external_layout a reçu la variable address. La durée vaut 24 jours : c'est l'emprunt prolongé de dix jours par l'assistant de l'article précédent.

Plusieurs emprunts cochés dans la liste, puis « Fiche de prêt » dans le menu Actions : un seul PDF, une page par emprunt (vérifié avec deux emprunts : deux pages), nommé d'après l'action puisque print_report_name ne s'applique qu'à un enregistrement seul.

6. Le moteur PDF, devenu un module

Jusqu'en 19, le module base appelait lui-même wkhtmltopdf. En Odoo 20, base ne sait plus produire de PDF : ses méthodes de rendu lèvent NotImplementedError, et le travail est confié à un module moteur. Deux sont livrés :

ModuleMoteurInstallation
base_report_wkhtmltoxwkhtmltopdf (et wkhtmltoimage)automatique, sans dépendance : présent sur toute base
base_report_paper_muncherPaper Muncher, le moteur maison d'Odooà installer soi-même

À son installation, base_report_wkhtmltox écrit le paramètre système report.pdf_engine_default = wkhtmltopdf. Le moteur d'un rapport se choisit ainsi : un report_type de la forme qweb-pdf-<moteur> l'impose ; sinon, le paramètre système décide ; sinon, wkhtmltopdf. Notre fiche, en qweb-pdf tout court, suit donc le paramètre. Interrogé en console sur la base de l'article :

R = env['ir.actions.report']
rep = env.ref('biblio.action_report_library_loan')
R._get_pdf_engine(rep)                     # moteur retenu pour ce rapport
R.get_pdf_engine_state('wkhtmltopdf')      # binaire trouvé et utilisable ?
[k for k, _ in R._fields['report_type'].selection]
'wkhtmltopdf'
'ok'
['qweb-html', 'qweb-pdf', 'qweb-text', 'qweb-pdf-wkhtmltopdf']

L'état vaut install quand le binaire est introuvable, upgrade sous la version 0.12.0, workers si le serveur est lancé avec --workers=1 (le mode sans processus de travail, workers = 0, imprime normalement), broken si le binaire répond sans version lisible. Dans ces cas, l'impression s'arrête sur un message d'erreur (en anglais dans le source : « Unable to find the pdf engine on this system… » pour le premier, traduit dans l'interface) au lieu de produire un fichier. C'est la première chose à regarder quand un serveur refuse d'imprimer.

Venant de la 19 : les appels directs à wkhtmltopdf changent de nom

Le code qui interrogeait le moteur à la main casse bruyamment : get_wkhtmltopdf_state() n'existe plus (AttributeError en console), remplacé par get_pdf_engine_state('wkhtmltopdf') ; la route /report/check_wkhtmltopdf devient /report/get_pdf_engine_state ; _run_wkhtmltopdf(bodies, …) cède la place à _run_pdf_engine_without_processing(engine_name, bodies, …). Un rapport déclaré en XML et imprimé par report_action() ou _render_qweb_pdf() n'est pas concerné : aucune dépendance à ajouter, _render_qweb_pdf(report_ref, res_ids, data) garde sa signature.

7. Déboguer sans générer de PDF

Un PDF se relit mal quand une case est vide ou qu'un bloc déborde. Le même rapport existe en HTML, derrière une route du client web, pour une session connectée :

# la page HTML, inspectable dans le navigateur
http://localhost:8069/report/html/biblio.report_library_loan/27
# le PDF, sans passer par le bouton
http://localhost:8069/report/pdf/biblio.report_library_loan/27
# plusieurs emprunts : identifiants séparés par des virgules
http://localhost:8069/report/pdf/biblio.report_library_loan/26,27

27 est l'identifiant de l'emprunt en base (celui de l'adresse de sa fiche), pas sa référence. Appelées avec la session de l'accueil, les trois adresses répondent 200 ; un identifiant inexistant répond 404 « Enregistrement inexistant ou supprimé ». En console, les mêmes rendus s'obtiennent par _render_qweb_html('biblio.action_report_library_loan', ids) et _render_qweb_pdf(...), qui renvoient le contenu et son type ('html', 'pdf').

Récapitulatif

  • Un rapport PDF = une action ir.actions.report + un gabarit QWeb + un moteur.
  • binding_type="report" range l'impression dans le menu Actions ; report_action() sert au bouton.
  • L'enveloppe boucle sur docs, le document s'habille de web.external_layout.
  • En Odoo 20, t-esc ne rend rien et un t-set dans le corps d'un t-call n'arrive pas : t-out et attributs.
  • Le premier administrateur qui imprime passe par le configurateur ; ses styles de tableau remplacent les anciens agencements rayé, encadré et gras.
  • Le moteur PDF vit dans base_report_wkhtmltox, installé d'office ; get_pdf_engine_state() dit s'il peut travailler.

L'adhérent repart avec sa fiche. Prochaine étape de la série : regarder les emprunts autrement qu'en liste — une vue kanban par état, un graphique des prêts par mois, un tableau croisé par genre.
