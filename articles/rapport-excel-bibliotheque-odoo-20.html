Le rapport Excel de la Bibliothèque : Binary sans base64

Un assistant qui écrit la liste des emprunts dans un vrai classeur .xlsx, le range dans un champ Binary et le propose au téléchargement. En Odoo 20, le geste de la version précédente, base64.b64encode, lève une erreur : le champ attend un BinaryValue, et l'ORM ne repasse en base64 que pour le client web.

~12 minutes de lecture · niveau intermédiaire · parcours Framework & ORM

Ce que tu vas apprendre

Écrire un classeur

xlsxwriter en mémoire : formats, dates, formules, volets figés, filtre et mise en page, sans les cellules FAUX ni les dates en nombre.

Le Binary d'Odoo 20

BinaryBytes à l'écriture, .content à la lecture, ce qui lève TypeError, et ce que devient datas= sur une pièce jointe.

Servir et protéger

Le téléchargement par /web/content, une restriction ir.access pour que chacun ne voie que son classeur, et un test Python du rapport.

Prérequis

  • Le module biblio de la série, jusqu'à l'API JSON-2 (étape 21) ; l'étape 22, sur l'import du catalogue, le porte en 20.0.1.20.0. On le fait passer ici en 20.0.1.21.0. Le code ajouté ne s'appuie que sur les emprunts et le groupe Bibliothécaire.
  • Le patron de l'assistant, vu à l'étape de l'assistant de prolongation, et le fichier ir.access.csv des droits d'accès.
  • XlsxWriter 3.1.9 et openpyxl 3.1.2, tous deux inscrits dans le requirements.txt d'Odoo 20 pour Python 3.12 : rien à ajouter au manifeste.

Le rapport PDF de l'étape 13 répond à l'impression. Pour retravailler des chiffres, trier ou recouper, il faut un classeur. Le chemin tient en cinq étapes.

1. Ce qu'un champ Binary accepte en Odoo 20

Commençons par le point qui casse tous les exports écrits pour la version précédente. Essai dans odoo-bin shell, sur l'assistant que l'on va construire ; contenu contient les octets du classeur :

import base64
from odoo.tools import BinaryBytes

export.file_data = base64.b64encode(contenu)                 # l'écriture habituelle en 19
export.file_data = contenu                                   # des octets nus
export.file_data = BinaryBytes(contenu, filename=export.file_name)   # la bonne écriture
export.file_data = base64.b64encode(b"abc").decode()         # une chaîne de caractères
TypeError: library.loan.export.file_data: use BinaryValue instead of bytes
TypeError: library.loan.export.file_data: use BinaryValue instead of bytes
(accepté)
(accepté : décodé, export.file_data.content vaut b'abc')

Le code du champ dit pourquoi les octets nus sont refusés : « we used to write base64 encoded data and we cannot distinguish whether bytes are encoded or not in base64 ». Odoo préfère s'arrêter que de ranger dans la base du base64 qu'il prendrait pour le contenu du fichier. Le champ raw de ir.attachment est la seule exception, puisqu'on sait qu'il est brut. Une str, elle, continue d'être décodée comme du base64 : c'est la forme qui arrive par RPC.

Odoo 19 → Odoo 20

En 19.0, le champ transporte du base64 : convert_to_column le pose dans la colonne tel qu'il arrive, et l'assistant d'export des traductions écrit base64.encodebytes(buf.getvalue()). Le même assistant, en 20.0 :

- out = is_exported and base64.encodebytes(buf.getvalue())
+ out = is_exported and BinaryBytes(buf.getvalue())

Lecture aussi : la valeur d'un champ est un BinaryValue, pas des bytes ni du base64.

À la lecture, on passe par les propriétés de l'objet. Valeurs relevées sur le classeur généré plus bas :

valeur = export.file_data
print(type(valeur).__name__, valeur.size, valeur.content[:4], valeur.filename, valeur.mimetype)
print(valeur.to_base64()[:12])
print(export.read(['file_data'])[0]['file_data'].keys())
BinaryBytes 6516 b'PK\x03\x04' emprunts_20260101_20261111.xlsx application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
UEsDBBQAAAAI
dict_keys(['filename', 'content', 'size'])

Le base64 n'a pas disparu : read() en sert un dans content, pour le client web. Simplement, il n'est plus dans le code du module.

2. L'assistant : deux états, un fichier

Un nouveau fichier wizard/library_loan_export.py, importé dans wizard/__init__.py. L'assistant a deux états : choose pour la saisie, get quand le fichier est prêt.

import io

from odoo import api, fields, models
from odoo.exceptions import UserError, ValidationError
from odoo.fields import Domain
from odoo.tools import BinaryBytes, date_utils


class LibraryLoanExport(models.TransientModel):
    _name = 'library.loan.export'
    _description = "Exporter les emprunts vers Excel"
    # Explicite : en 20.0, la valeur héritée tombe à 0 dans la tâche de nettoyage.
    _transient_max_hours = 1.0

    date_from = fields.Date(
        string="Emprunts du",
        required=True,
        default=lambda self: date_utils.start_of(fields.Date.context_today(self), 'year'),
    )
    date_to = fields.Date(string="au", required=True, default=fields.Date.context_today)
    scope = fields.Selection(
        [
            ('all', "Tous"),
            ('ongoing', "En cours"),
            ('late', "En retard"),
        ],
        string="Emprunts à inclure",
        default='all',
        required=True,
    )
    state = fields.Selection([('choose', "Choix"), ('get', "Fichier prêt")], default='choose')
    loan_count = fields.Integer(string="Emprunts exportés", readonly=True)
    # Le fichier : des octets bruts dans un BinaryValue, plus de base64 en 20.0.
    file_data = fields.Binary(string="Classeur", readonly=True, attachment=False)
    file_name = fields.Char(string="Nom du fichier", readonly=True)

    @api.constrains('date_from', 'date_to')
    def _check_dates(self):
        for export in self:
            if export.date_from > export.date_to:
                raise ValidationError(self.env._("La date de début doit précéder la date de fin."))

attachment=False range le fichier dans une colonne bytea de la table de l'assistant, au lieu de créer une pièce jointe. C'est ce que fait aussi l'assistant d'export des traductions du cœur. Le fichier disparaît avec la ligne de l'assistant, à la purge périodique (_transient_max_hours se déclare comme à l'étape 12), sans pièce jointe à nettoyer. Vérification dans PostgreSQL :

SELECT octet_length(file_data), encode(substring(file_data from 1 for 2), 'escape') FROM library_loan_export;
 6516 | PK

Le contenu de la colonne est bien le fichier, et non du texte base64.

Le champ file_name n'est pas un doublon. Le filename de BinaryBytes ne vit que dans la valeur en mémoire : relu depuis la base, il revient vide.

avant relecture   : 'emprunts_20260101_20261111.xlsx'
relu depuis la base : ''

Le nom doit donc rester dans un champ, et la vue l'indique au widget par filename="file_name".

3. Écrire le classeur avec xlsxwriter

Le filtrage d'abord, avec les emprunts triés par date, puis la construction du fichier. Une méthode qui rend des octets et ne touche à aucun enregistrement : c'est elle que l'on teste.

    def _get_loans(self):
        self.ensure_one()
        domain = Domain('date_out', '>=', self.date_from) & Domain('date_out', '<=', self.date_to)
        if self.scope == 'ongoing':
            domain &= Domain('state', '=', 'ongoing')
        elif self.scope == 'late':
            domain &= Domain('is_late', '=', True)
        return self.env['library.loan'].search(domain, order='date_out, reference')

    def _build_workbook(self, loans):
        """Rend le classeur .xlsx des emprunts, en octets."""
        import xlsxwriter  # noqa: PLC0415 (dépendance d'Odoo, importée à l'usage comme dans le cœur)

        etats = dict(loans._fields['state']._description_selection(self.env))
        colonnes = [
            (self.env._("Référence"), 16),
            (self.env._("Livre"), 32),
            (self.env._("Exemplaire"), 14),
            (self.env._("Adhérent"), 24),
            (self.env._("Emprunté le"), 13),
            (self.env._("À rendre le"), 13),
            (self.env._("Rendu le"), 13),
            (self.env._("État"), 10),
            (self.env._("Jours de retard"), 15),
        ]
        buffer = io.BytesIO()
        with xlsxwriter.Workbook(buffer, {'in_memory': True}) as classeur:
            feuille = classeur.add_worksheet(self.env._("Emprunts"))
            entete = classeur.add_format({
                'bold': True, 'font_color': '#FFFFFF', 'bg_color': '#017E84', 'border': 1,
            })
            date = classeur.add_format({'num_format': 'dd/mm/yyyy'})
            retard = classeur.add_format({'bold': True, 'font_color': '#B91C1C'})
            total = classeur.add_format({'bold': True, 'top': 1})

            for col, (titre, largeur) in enumerate(colonnes):
                feuille.write(0, col, titre, entete)
                feuille.set_column(col, col, largeur)

            for ligne, emprunt in enumerate(loans, start=1):
                feuille.write_string(ligne, 0, emprunt.reference)
                feuille.write_string(ligne, 1, emprunt.book_id.title or "")
                feuille.write_string(ligne, 2, emprunt.copy_id.name or "")
                feuille.write_string(ligne, 3, emprunt.member_id.name or "")
                for col, valeur in ((4, emprunt.date_out), (5, emprunt.date_due), (6, emprunt.date_return)):
                    if valeur:  # une date vide vaut False : write() l'écrirait comme booléen FAUX
                        feuille.write_datetime(ligne, col, valeur, date)
                feuille.write_string(ligne, 7, etats.get(emprunt.state, ""))
                feuille.write_number(ligne, 8, emprunt.days_late, retard if emprunt.days_late else None)

            fin = len(loans) + 1
            feuille.write_string(fin, 0, self.env._("Total"), total)
            feuille.write_formula(fin, 1, f'=COUNTA(A2:A{fin})', total, len(loans))
            feuille.write_formula(fin, 8, f'=SUM(I2:I{fin})', total, sum(loans.mapped('days_late')))
            feuille.freeze_panes(1, 0)
            feuille.autofilter(0, 0, len(loans), len(colonnes) - 1)
            # À l'impression : A4 paysage, toutes les colonnes sur une page de large.
            feuille.set_paper(9)
            feuille.set_landscape()
            feuille.fit_to_pages(1, 0)
        return buffer.getvalue()

Quelques choix à relever :

  • import xlsxwriter dans la méthode, comme le fait le cœur dans web/controllers/export.py.
  • with xlsxwriter.Workbook(...) : le fichier ZIP n'est écrit dans le tampon qu'à la fermeture. Le getvalue() vient après le bloc.
  • self.env._() pour les titres et les libellés : ils seront traduits comme ceux des vues. Pour les états, on prend le libellé affiché de la sélection, pas la clé ongoing.
  • Formules avec valeur calculée : le dernier argument de write_formula est le résultat stocké. Sans lui, xlsxwriter stocke 0 : relu sans évaluation, =1+1 vaut 0.
  • Mise en page : A4, paysage, une page de large. C'est aussi ce qui a permis le rendu complet de la dernière figure.

write() sur une date : FAUX ou nombre

Un champ Date vide vaut False dans Odoo. La méthode générique write() de xlsxwriter en fait un booléen : la cellule affiche FAUX, relu par openpyxl comme False. Et une date écrite sans format devient un simple nombre : 2026-01-02 a été relu 46024, format General. D'où le test sur la valeur et l'appel explicite à write_datetime(ligne, col, valeur, date).

4. Ranger le fichier et le faire télécharger

    def action_generate(self):
        self.ensure_one()
        loans = self._get_loans()
        if not loans:
            raise UserError(self.env._("Aucun emprunt ne correspond à ces critères."))
        nom = f"emprunts_{self.date_from:%Y%m%d}_{self.date_to:%Y%m%d}.xlsx"
        self.write({
            'state': 'get',
            'loan_count': len(loans),
            'file_data': BinaryBytes(self._build_workbook(loans), filename=nom),
            'file_name': nom,
        })
        return {
            'type': 'ir.actions.act_window',
            'name': self.env._("Exporter les emprunts"),
            'res_model': self._name,
            'res_id': self.id,
            'view_mode': 'form',
            'views': [(False, 'form')],
            'target': 'new',
        }

    def action_download(self):
        self.ensure_one()
        return {
            'type': 'ir.actions.act_url',
            'url': f'/web/content/{self._name}/{self.id}/file_data/{self.file_name}?download=true',
            'target': 'download',
        }

action_generate rouvre le même enregistrement, au lieu de fermer la fenêtre : le formulaire passe à l'état get. L'utilisateur a alors deux moyens d'obtenir le fichier : le lien du champ, ou le bouton Télécharger, qui renvoie une action ir.actions.act_url. La réponse étant un fichier à télécharger (?download=true), la page ne change pas. Avec target: 'download', le client ne traite ni close ni onClose : la fenêtre de l'assistant reste ouverte après le téléchargement.

La route utilisée est celle du cœur, /web/content/<modèle>/<id>/<champ>/<nom>, ici avec ?download=true. Aucun contrôleur à écrire, et elle sert un champ attachment=False comme une pièce jointe. Réponse relevée pour le compte qui a généré le fichier :

200
Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
Content-Disposition: attachment; filename=emprunts_20260101_20261111.xlsx
6515 octets

Le type de contenu n'est écrit nulle part dans le module : Odoo le déduit du fichier. La taille bouge de quelques octets d'une génération à l'autre (6 515 ici, 6 516 dans les essais précédents), et le test HTTP de la section 8 compare les octets reçus au contenu du champ.

Un classeur qui se télécharge n'est pas encore un classeur correct. Le fichier obtenu par le navigateur, relu par openpyxl. Il lit soit les formules, soit leur dernière valeur calculée, d'où les deux ouvertures :

6. Chacun son classeur

Un modèle transitoire n'est pas privé par nature, et ce fichier contient les noms des adhérents. Deux lignes dans security/ir.access.csv :

access_library_loan_export_manager,Exporter les emprunts : assistant,library.loan.export,group_library_manager,cru,
restrict_library_loan_export_own,Exporter les emprunts : chacun son classeur,library.loan.export,,rud,"[('create_uid', '=', user.id)]"

La première est une permission (avec groupe), la seconde une restriction (sans groupe, appliquée à tous). Le résultat, pour un classeur généré par un bibliothécaire :

QuiEn PythonPar /web/content
Celui qui l'a générélit le fichier200
Un autre bibliothécaireAccessError404
Un administrateur (membre du groupe Bibliothécaire)AccessError404
Un agent d'accueil (sans le groupe)pas de droit de création, menu absent404
Sans session—404

Sans la restriction, l'autre bibliothécaire lit bien l'assistant : n'importe quel membre du groupe peut récupérer le fichier d'un collègue en changeant l'identifiant dans l'adresse. Une restriction sans groupe concerne tout le monde, administrateur compris ; seul sudo() passe outre.

7. Garder le fichier : ir.attachment

L'assistant jette son fichier à la purge. Pour le conserver, attaché à un emprunt par exemple, on crée une pièce jointe. Quatre essais avec les mêmes octets :

Attachment = env['ir.attachment']
base = {'res_model': 'library.loan', 'res_id': emprunt.id}

a = Attachment.create({**base, 'name': 'emprunts.xlsx', 'datas': base64.b64encode(contenu)})
b = Attachment.create({**base, 'name': 'emprunts.xlsx', 'raw': contenu})
c = Attachment.create({**base, 'raw': BinaryBytes(contenu, filename='emprunts.xlsx')})
Attachment.create({**base, 'raw': contenu})   # sans nom
datas= : file_size 0, raw vide     UserWarning: Use raw, datas has beeen removed
raw=   : file_size 6516, type application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
raw=BinaryBytes(filename=…) : name 'emprunts.xlsx', file_size 6516
sans nom : NotNullViolation: null value in column "name" of relation "ir_attachment" violates not-null constraint

datas= ne lève rien et crée une pièce jointe vide

La clé est retirée des valeurs et un simple avertissement part dans le journal. L'enregistrement existe, porte son nom, et le fichier fait 0 octet. On ne le découvre qu'en ouvrant le document. raw=, ici en bytes ou en BinaryBytes, est la seule écriture à retenir ; avec BinaryBytes et son filename, le name peut même être omis.

8. Tester le rapport

Le test relit le classeur avec openpyxl, comme on l'a fait à la main, et vérifie le refus du base64. Extrait de tests/test_loan_export.py (le fichier complet contrôle aussi le contenu des lignes, le filtre « En retard », l'absence d'emprunt et la mise en page) :

    def test_file_is_raw_xlsx(self):
        export = self._export()
        self.assertEqual(export.state, 'get')
        self.assertIsInstance(export.file_data, BinaryValue)
        # Des octets bruts : la signature ZIP d'un .xlsx, pas du base64.
        self.assertEqual(export.file_data.content[:2], b'PK')
        self.assertTrue(export.file_name.endswith('.xlsx'))
        self.assertEqual(export.loan_count, 3)

À retenir

  • En Odoo 20, un champ Binary reçoit un BinaryBytes : base64.b64encode lève TypeError.
  • Le nom du fichier n'est pas conservé par le champ : il faut un Char à côté.
  • Avec xlsxwriter, une date passe par write_datetime et un format, et jamais une valeur vide par write().
  • Un assistant n'est pas privé : une restriction create_uid empêche un collègue de récupérer le fichier par son adresse.
