Odoo 20 : comptes parents, codes et amortissements

Trois mécaniques du plan comptable changent entre Odoo 19 et Odoo 20 : les groupes de comptes laissent la place aux comptes parents, le code d'un compte devient facultatif, et les modèles d'amortissement ne portent plus les comptes. Cet article montre ce que le responsable comptable doit revoir, écran par écran, avant de travailler en Odoo 20.

~12 minutes de lecture · niveau intermédiaire · série Passer à Odoo 20

Édition : Enterprise, avec un encadré Community. Écrit et vérifié sur Odoo 20.0 Enterprise (base hébergée sur odoo.com), novembre 2026, avec les sociétés de démonstration « FR Company » (plan comptable français) et « My US Company » (plan des États-Unis). Ce qui concerne la Community est vérifié sur une copie de la base de démonstration d'Odoo 20.0 Community. Les comparaisons avec Odoo 19 s'appuient sur le code source de la version 19.0 et, pour l'Enterprise, sur la documentation officielle 19.0.

Pourquoi revoir son plan comptable en passant à Odoo 20

Entre Odoo 19 et Odoo 20, ce qui change dans le plan comptable, c'est la façon dont Odoo regroupe les comptes, ce qu'il exige d'un compte, et l'endroit où il range les réglages d'amortissement. Trois habitudes d'Odoo 19 ne donnent donc plus le même résultat : lire une balance par groupes de comptes, compter sur un code toujours présent, modifier un modèle d'immobilisation pour changer les comptes de dotation.

Cet article ne reprend pas le fonctionnement des immobilisations ni celui des rapports : ils sont décrits dans Immobilisations, amortissements et budgets avec Odoo 20 et Bilan, compte de résultat et TVA avec Odoo 20. Il se concentre sur ce qui a changé depuis Odoo 19 et sur les contrôles à faire. Le catalogue complet des nouveautés se trouve dans Les nouveautés d'Odoo 20.

Objectifs

À la fin de cet article, vous saurez :

  • reconnaître un compte parent dans le plan comptable d'Odoo 20 et en créer un ;
  • lire ce qu'un compte parent totalise dans la balance générale ;
  • repérer les comptes sans code et mesurer l'effet d'un compte sans code sur l'export FEC ;
  • retrouver les réglages d'amortissement, partagés entre le modèle et le compte d'immobilisation ;
  • savoir ce que la Community propose sur ces trois sujets.

1. Où se trouvent ces réglages

Enterprise. Dans l'application Comptabilité, ouvrez le menu Configuration. Le plan comptable et les modèles d'amortissement figurent sous la rubrique Comptabilité. La capture a été prise en mode développeur, celui où Odoo 19 affichait aussi l'écran des groupes de comptes : en Odoo 20, cette entrée n'existe plus.

Les autres entrées (taxes, journaux, rapports, contrôles…) ne font pas l'objet de cet article. Seule Multinormes comptables sera citée plus loin, parce qu'un champ de la fiche du compte d'immobilisation y renvoie.

2. Des groupes de comptes aux comptes parents

En Odoo 19, un groupe de comptes réunissait tous les comptes dont le code tombait dans une plage de préfixes : le compte 131200 entrait de lui-même dans le groupe 131000. La documentation officielle 19.0 montre la balance de l'Enterprise présentée par groupes grâce à l'option « Hierarchy and Subtotals ». Le regroupement dépendait donc du code.

Odoo 20 supprime le modèle des groupes de comptes. Le regroupement devient un compte comme un autre, désigné dans le champ Compte parent de chaque compte enfant. Dans les plans comptables livrés avec Odoo 20, 23 plans (21 pays, dont les États-Unis) ont vu leurs anciens groupes transformés en comptes parents archivés. Le plan français n'en fait pas partie : il est livré sans groupe et sans compte parent. Ces constats portent sur les plans livrés neufs : sur une base migrée, vérifiez ce que sont devenus vos groupes de comptes.

Le plan de la société de démonstration « My US Company » montre le résultat. Ouvrez Comptabilité › Configuration › Plan comptable avec cette société active, puis passez à la seconde page de la liste.

Travel Expenses est un compte parent archivé, d'où sa couleur grise. Ses quatre comptes enfants le suivent, légèrement en retrait. La liste affiche un compte archivé dès qu'il a des enfants actifs ; le retrait n'apparaît que dans la liste brute, sans filtre, sans tri par colonne ni regroupement. La colonne Code est vide : ce plan est livré sans code, point traité à la section 5. Utilities, en bas, est un autre parent archivé ; ses enfants suivent sur la page.

3. Créer un compte parent dans le plan français

Enterprise. Le plan français ne propose aucun regroupement : c'est au responsable comptable de créer les comptes parents dont ses analyses ont besoin. L'exemple réunit sous un parent « 60 Achats » les deux comptes de charges mouvementés de la société de démonstration FR Company.

Dans Comptabilité › Configuration › Plan comptable, cliquez sur Nouveau. Saisissez le code 60, le nom Achats et choisissez le type Charges. Laissez le champ Compte parent vide (texte indicatif « Compte racine ») : ce compte est lui-même au sommet. Enregistrez.

Le code 60 n'est pas obligatoire. Il sert ici à classer le parent : la liste du plan comptable trie les comptes par la suite des codes de leurs parents, ce qui place les enfants juste après le compte 60.

Ouvrez ensuite le compte 606300 Entretien et petit matériel. Dans le champ Compte parent, tapez 60 et choisissez « 60 Achats ». Enregistrez, puis faites de même pour 607000 Marchandises.

Le rattachement ne touche ni le type, ni les taxes par défaut, ni les étiquettes du compte enfant. Revenez enfin sur le compte 60 et désactivez Actif : le parent est archivé, comme ceux que livre Odoo pour le plan des États-Unis. Le premier point de vigilance explique pourquoi.

Le compte 601000, qui n'a pas été rattaché, vient après le groupe sans retrait : seul le champ Compte parent crée le lien, le code n'y est pour rien. L'ordre suit les codes des parents : « 60 / 606300 » se classe avant « 601000 », d'où 606300 et 607000 avant 601000.

4. Ce que le parent totalise dans la balance

Enterprise. Ouvrez Comptabilité › Analyse › Balance générale. Sur le plan français d'origine, le menu des options (le bouton « Pièces comptabilisées, Comptabilité d'engagement ») ne propose pas de sous-totaux. L'option Sous-totaux apparaît dès que le plan contient un compte parent : cochez-la.

La ligne 60 Achats porte la somme de ses enfants, colonne par colonne : 2 142,27 € en solde initial comme en solde final, aucun mouvement en novembre. Un clic la replie ou la déplie. Le total reste le même que le parent soit actif ou archivé. Les autres comptes, sans parent, restent sur une ligne chacun.

Pour essayer ces écrans sur une base à soi, une base d'essai s'ouvre depuis le site d'Odoo, en choisissant l'application Comptabilité.

Le bilan et le compte de résultat ont leurs propres lignes, définies par les rapports de la localisation : leur lecture est décrite dans Bilan, compte de résultat et TVA avec Odoo 20. Le présent article n'a vérifié l'effet des comptes parents que sur la balance générale.

5. Des codes de compte facultatifs

Odoo 19 refusait d'enregistrer un compte sans code, avec le message « The code must be set for every company to which this account belongs ». Odoo 20 retire ce contrôle : un compte peut n'avoir qu'un nom. Le plan des États-Unis en tire parti, ses 134 comptes de démonstration n'ont aucun code (figure 3). Le code accepte aussi désormais les tirets, en plus des lettres, des chiffres et des points.

Le plan français, lui, garde ses codes. La question se pose pour les comptes ajoutés à la main : rien n'oblige plus à leur donner un code. L'export FEC lit pourtant le code du compte pour remplir la colonne CompteNum. L'essai a été fait sur une copie Community de la base de démonstration (société FR Company) : un compte créé sans code, une opération diverse de 80 € comptabilisée sur ce compte, puis l'assistant d'export FEC lancé en mode test.

Extrait du fichier obtenu (colonnes choisies) :

Dans la liste du plan comptable, un compte sans code se repère à sa colonne Code vide. En Enterprise, l'export FEC se lance depuis le menu du rapport Grand livre général (entrée FEC) ; hors mode test, l'export enregistre la fin de la période exportée comme date de verrouillage de l'exercice, si celle-ci est vide ou antérieure.

6. Les modèles d'amortissement

Enterprise. En Odoo 19, la documentation officielle décrit des Asset Models (Comptabilité › Configuration). Un modèle y réunissait la méthode, la durée, le journal et les deux comptes des dotations : compte d'amortissement et compte de charge. Le compte d'immobilisation portait de son côté un réglage d'automatisation (création manuelle, création en brouillon, ou création et validation) et le modèle à appliquer. Le code source de la Community 19 le confirme à sa façon : les données du plan comptable des États-Unis déclaraient ces modèles comme des immobilisations et les reliaient aux comptes.

Odoo 20 sépare les deux rôles. Ouvrez Comptabilité › Configuration › Modèles d'amortissement.

Un modèle d'amortissement ne contient plus que la méthode (Mode, Basé sur une durée ou un taux, Durée, Calcul), la part non amortissable, la société et le journal. Les noms « 3 Year », « 5 Year »… sont générés à partir de ces réglages, tant qu'aucun nom n'a été saisi à la main. Selon l'aide du champ, le journal se règle société par société.

Le modèle 3 Year sert déjà à une immobilisation (bouton Immobilisation(s)). Ses champs Mode, Basé sur et Durée sont grisés : selon l'aide d'Odoo, un modèle utilisé par une immobilisation confirmée, en attente ou clôturée a sa configuration d'amortissement figée. Le modèle 4 Year, qui n'en a aucune, reste modifiable.

Les comptes ont rejoint la fiche du compte d'immobilisation. Ouvrez le compte 218300 depuis le plan comptable.

La section Amortissement du compte réunit :

  • Amortissement : le modèle proposé par défaut sur une facture fournisseur ou un avoir qui utilise ce compte (3 Year pour 218300) ;
  • Amortissement cumulé : le compte crédité par les dotations (281800) ;
  • Compte de charge de l'actif : le compte débité (681120) ;
  • Multi-grands livres, vide ici : il sert aux bases qui tiennent plusieurs normes comptables, réglées dans Configuration › Multinormes comptables, hors du champ de cet article.

La fiche n'offre plus de réglage d'automatisation. Le plan comptable français des sociétés d'Odoo 20 relie d'office 25 comptes d'immobilisation à un modèle : 3 ans pour 218300 et 218600, 4 ans pour le matériel de transport 218200, 5, 10 ou 20 ans pour les autres. Ce qui se passe ensuite sur la facture fournisseur (modèle proposé sur la ligne, immobilisation créée à la confirmation) est montré pas à pas dans Immobilisations, amortissements et budgets avec Odoo 20.

Après la migration, relisez donc chaque compte d'immobilisation utilisé : modèle par défaut, compte d'amortissement cumulé et compte de charge. Ce sont eux, et non plus le modèle, qui décident des comptes des futures dotations.

Et en Community ?

Les comptes changent aussi, mais l'écran du plan comptable est masqué

Les comptes parents et les codes facultatifs viennent du module de facturation : ils existent dans Odoo 20 Community. Sur la base de démonstration, l'administrateur n'a pourtant que l'application Facturation, dont le menu Configuration ne propose pas le plan comptable, même en mode développeur : ce menu est réservé à un droit (la case technique « Montrer les fonctions de comptabilité complètes » de la fiche utilisateur, visible en mode développeur) que l'administrateur de démonstration n'a pas.

L'assistant d'export FEC utilisé à la section 5 appartient à la Community, mais il n'y a ni menu ni action pour l'ouvrir. La balance générale et ses sous-totaux sont des rapports de l'Enterprise. Enfin, aucun module d'immobilisations ne figure dans le dépôt Community : pas de modèles d'amortissement. Les liens entre comptes et modèles prévus par le plan comptable français ne servent qu'avec l'application Enterprise.

Points de vigilance

Un compte parent actif accepte des écritures

Odoo n'empêche pas de comptabiliser sur un compte qui a des enfants : l'essai sur une copie de la démonstration a passé une écriture sur un parent actif sans message. Archivé, le même compte est refusé (« Le compte … est archivé. »). Archivez vos comptes parents, comme ceux que livre Odoo, pour qu'ils ne servent qu'au regroupement.

Le plan français d'Odoo 20 ne regroupe rien

Livré sans groupe ni compte parent, il n'offre pas l'option Sous-totaux dans la balance générale. Si vos analyses d'Odoo 19 s'appuyaient sur les groupes de comptes, vérifiez après la migration ce que la balance propose, et créez les comptes parents dont vous avez besoin.

Un modèle d'amortissement utilisé ne se modifie plus

Dès qu'une immobilisation confirmée l'utilise, la méthode et la durée du modèle sont figées. Pour une nouvelle règle, créez un nouveau modèle, puis choisissez-le comme modèle par défaut sur les comptes d'immobilisation concernés.

Exercice

Objectif : regrouper les frais de missions sous un compte parent et lire son total dans la balance générale.

Indication : sur une base Enterprise au plan comptable français, choisissez un compte de classe 62 qui a des écritures. Créez un compte « 62 Autres services extérieurs » de type Charges, rattachez-lui ce compte, archivez le compte 62, puis ouvrez la balance générale avec l'option Sous-totaux.

Critère de réussite : la balance affiche une ligne « 62 Autres services extérieurs » dont le solde égale celui du compte rattaché, et la liste du plan comptable montre 62 en gris avec le compte rattaché en retrait.

À retenir

  • Les groupes de comptes n'existent plus : un regroupement est un compte, désigné par le champ Compte parent de chaque enfant.
  • Un compte parent se crée comme un autre compte et s'archive pour ne pas recevoir d'écritures ; la balance générale le totalise avec l'option Sous-totaux.
  • Le plan français d'Odoo 20 n'a ni groupe ni parent : les regroupements sont à créer.
  • Le code d'un compte est facultatif, mais l'export FEC en a besoin : en France, gardez un code à chaque compte mouvementé.
  • Le modèle d'amortissement ne porte plus que la méthode, la durée et le journal ; le modèle par défaut et les comptes des dotations se règlent sur le compte d'immobilisation.
