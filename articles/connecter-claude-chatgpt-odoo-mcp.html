Connecter Claude ou ChatGPT à Odoo 20 par MCP

Odoo 20 Enterprise contient un serveur MCP : un assistant comme Claude ou ChatGPT peut interroger la base et, si l'administrateur l'autorise, y écrire, au nom d'un utilisateur et avec ses droits. Autoriser l'assistant, créer la clé, choisir les outils, retirer l'accès.

~11 minutes de lecture · niveau intermédiaire · série L'IA au travail dans Odoo 20

Édition : Enterprise. Écrit et vérifié sur Odoo 20.0 Enterprise (base hébergée sur odoo.com), novembre 2026, avec Claude Code comme assistant. Ce qui concerne ChatGPT provient de la documentation officielle d'Odoo 20.

Poser une question sur ses ventes à un assistant conversationnel, sans exporter de fichier ni recopier de chiffres : c'est ce que permet le MCP (Model Context Protocol), un standard ouvert par lequel un assistant d'intelligence artificielle appelle les outils d'une application. Odoo 20 Enterprise joue le rôle de serveur MCP : l'assistant s'y connecte à l'adresse de la base suivie de /mcp, choisit les outils dont il a besoin (rechercher, regrouper, créer…) et formule la réponse.

Le serveur est fourni par le module AI MCP Server, installé automatiquement avec l'application IA. Il ne demande aucun développement. Il n'agit jamais en son nom propre : chaque appel est fait au nom d'un utilisateur Odoo, avec ses droits. L'IA intégrée à Odoo, ses agents et le bouton « Demander à l'IA », est présentée dans L'IA dans Odoo 20 : agents, questions et rédaction ; cet article traite de l'autre sens, un assistant extérieur qui vient chercher les données.

Objectifs

À la fin de cet article, vous saurez :

  • autoriser un assistant par OAuth, ou créer une clé API de portée MCP ;
  • déclarer le serveur Odoo dans Claude Code sans écrire la clé dans un fichier ;
  • vérifier qu'un utilisateur aux droits restreints obtient moins de réponses qu'un administrateur ;
  • choisir les outils exposés, en particulier ceux qui écrivent ;
  • retirer l'accès d'un assistant.

Le chemin d'une question

L'assistant reçoit la question en langage courant et interroge le serveur MCP d'Odoo. Pour être accepté, il présente soit une clé API de portée MCP, soit un accès accordé par OAuth sur la page Grant Access d'Odoo. Dans les deux cas, Odoo sait quel utilisateur se trouve derrière. Deux filtres s'appliquent alors : la liste des outils disponibles en MCP, réglée par l'administrateur, et les droits de l'utilisateur (groupes, règles d'accès, sociétés autorisées). L'assistant rédige sa réponse avec ce qui a passé les deux filtres.

1. Les assistants autorisés : le réglage MCP OAuth

Ouvrez Paramètres et, dans la rubrique des intégrations, repérez le bloc MCP OAuth.

Le texte du bloc l'explique : seuls les assistants dont l'adresse de description (un document appelé CIMD) figure dans cette liste peuvent obtenir un accès par OAuth. Odoo 20 en propose quatre : celle de ChatGPT, deux adresses du domaine de Claude (dont celle de Claude Code) et celle de Grok. Pour autoriser un autre assistant qui publie un tel document, la documentation d'Odoo indique d'ajouter son adresse sur une nouvelle ligne et d'enregistrer.

La case Allow Dynamic Client Registration (DCR), décochée, laisserait n'importe quel assistant s'enregistrer lui-même. Elle sert aux assistants qui ne publient pas de document CIMD.

2. Première voie : accorder l'accès par OAuth

OAuth est la méthode que recommande la documentation d'Odoo, réservée aux utilisateurs internes (un utilisateur du portail passe par une clé API). Côté assistant, il suffit de déclarer l'adresse du serveur, sans clé :

  • dans Claude Code, la documentation donne la commande claude mcp add --transport http <nom> <adresse-de-la-base>/mcp ;
  • dans ChatGPT, toujours selon la documentation d'Odoo 20 : Settings › Plugins › Add custom MCP server, un nom, l'adresse <adresse-de-la-base>/mcp et l'authentification OAuth.

L'assistant ouvre alors la page de connexion d'Odoo dans le navigateur. Une fois l'utilisateur connecté, Odoo affiche la page Grant Access.

La page nomme l'assistant (ici Claude Code), propose une durée d'accès, 1 Month présélectionné, et deux boutons : Allow accorde l'accès, Deny le refuse. Le cadre « Your logo » est l'emplacement du logo de la société, vide sur la base de démonstration. D'après la documentation, l'accès accordé apparaît ensuite comme une clé API dans les préférences de l'utilisateur, et l'assistant redemande une connexion quand il expire.

3. Seconde voie : une clé API de portée MCP

Quand l'assistant ne gère pas OAuth, ou pour un utilisateur du portail, l'utilisateur crée lui-même une clé. Cliquez sur votre avatar, en haut à droite, puis sur Mes préférences, onglet Sécurité.

Le bloc Clés API porte la mention « Connect via RPC or MCP ». Cliquez sur Create API Key : Odoo demande d'abord de confirmer le mot de passe (fenêtre Contrôle d'accès), puis ouvre la fenêtre de création.

  • Key Name : un nom qui dit à quoi sert la clé ; c'est le seul moyen de la reconnaître ensuite.
  • Scope : MCP. La portée RPC sert aux scripts et intégrations qui appellent l'API d'Odoo.
  • Expires : de 1 Day à Never. Une durée courte limite les dégâts d'une clé égarée.

Create Key affiche la clé, une seule fois.

La fenêtre rappelle que la clé ne sera plus affichée et qu'elle donne un accès complet au compte. L'encadré du bas donne les trois réglages à reporter dans l'assistant : l'adresse du serveur (celle de la base suivie de /mcp), un nom au choix, et l'en-tête Authorization: Bearer suivi de la clé. Copiez la clé avant de cliquer sur Done, I have saved it.

4. Déclarer le serveur dans Claude Code

Dans un terminal, depuis le dossier du projet, la commande suivante déclare le serveur Odoo sous le nom odoo. La clé n'y figure pas : elle est lue dans la variable d'environnement ODOO_MCP_KEY, définie dans la session du terminal.

claude mcp add --scope project --transport http odoo https://votre-base.odoo.com/mcp --header 'Authorization: Bearer ${ODOO_MCP_KEY}'

Claude Code répond « Added HTTP MCP server odoo ». Avec l'option --scope project, il range la déclaration dans le fichier .mcp.json du projet, qui contient ${ODOO_MCP_KEY} et non la clé. Ce fichier peut donc être partagé avec l'équipe : chacun y branche sa propre clé. Au premier lancement, Claude Code demande d'approuver ce serveur déclaré par le projet. La documentation d'Odoo décrit aussi une variante qui passe par l'outil mcp-remote (Node.js), valable aussi pour Claude Desktop.

Pour vérifier l'effet des droits, posez la même question avec deux clés : celle d'un administrateur, puis celle d'un commercial dont le droit Ventes est Utilisateur : mes documents seulement. Les figures suivantes montrent Claude Code en mode non interactif (option -p), limité au serveur du projet, avec les outils Odoo approuvés d'avance (option --allowedTools).

Avec la clé de l'administrateur, l'assistant compte 13 devis en brouillon, 22 pistes et 18 opportunités.

Pour essayer sur une base à soi, une base d'essai d'Odoo Enterprise s'ouvre depuis le site d'Odoo ; le serveur MCP accompagne l'application IA.

Avec la clé du commercial, la même question donne 0 devis et 13 pistes. Aucun des 13 devis en brouillon n'est à son nom (ils appartiennent à trois autres vendeurs), et la base compte exactement 13 pistes sans vendeur, que la règle « mes documents seulement » laisse visibles. Les opportunités des autres vendeurs lui restent cachées. L'écart ne se limite pas aux données : l'outil qui liste les modèles accessibles en renvoie 629 pour l'administrateur et 301 pour le commercial. L'assistant n'a contourné aucune règle : il a interrogé Odoo avec les droits du commercial.

La réponse reste une rédaction de l'assistant. Le mot « pistes » est ambigu : un assistant peut le comprendre comme « opportunités ». Une question précise appelle une réponse précise, et un chiffre important se recoupe avec l'écran d'Odoo.

5. Les outils exposés : lire d'office, écrire sur décision

Les outils que voit l'assistant sont des actions de serveur. Activez le mode développeur, puis ouvrez Paramètres › Technique › Actions › Actions de serveur et recherchez « Outil IA ».

Cliquez sur l'en-tête Disponible en MCP (titre tronqué à l'écran, comme celui de la colonne Outil d'accès en lecture) pour remonter les lignes cochées : la liste montre les cinq outils exposés d'office : lire le groupe (totaux et comptages), obtenir les champs, rechercher, obtenir les modèles, et récupérer le contexte initial (utilisateur, société active, sociétés autorisées). Tous lisent ; aucun n'écrit. Sur cette base, les 42 autres, dont les outils de l'IA intégrée comme « ajouter des étiquettes » sur les documents, restent invisibles pour l'assistant.

Pour lui permettre d'écrire, ouvrez l'outil voulu, par exemple Outil IA : créer des enregistrements, onglet Utilisation.

La case Disponible en MCP expose l'outil, sous le nom technique affiché à côté de « Utiliser dans l'IA » (ai_tool_create_records). La case Outil d'accès en lecture reste décochée : selon la documentation, elle indique seulement à l'assistant qu'il peut appeler l'outil sans demander l'accord de l'utilisateur ; elle n'empêche aucune écriture. L'outil de mise à jour, Outil IA : mettre à jour les enregistrements, se règle de la même façon.

Une fois l'outil exposé, une demande de création de contact, avec un nom et une adresse électronique, aboutit.

Le contact est créé, et le fil de discussion l'attribue à Formateur Odoo, le compte administrateur de la base dont la clé a servi : rien n'y indique qu'un assistant a fait la saisie. Avec la clé du commercial, une demande de création de liste de prix échoue avec le message d'Odoo « You are not allowed to create 'Pricelist' (product.pricelist) records », suivi des groupes qui en ont le droit, que l'assistant transmet.

6. Retirer l'accès

Toute connexion, par OAuth ou par clé, se retrouve dans Mes préférences › Sécurité, bloc Clés API.

La clé porte son nom, le badge MCP, sa date de création et sa date d'expiration. Supprimer la révoque aussitôt : le serveur refuse ensuite la clé, et l'assistant ne peut plus rien lire ni écrire. Sans suppression, la clé expire d'elle-même à la date indiquée par « Expire le ».

Et en Community ?

Des clés API, pas de serveur MCP

Odoo 20 Community ne contient ni l'application IA ni le module AI MCP Server : l'adresse /mcp n'y existe pas. Les clés API y existent, mais avec une seule portée, RPC, et la fenêtre de création n'affiche alors pas le choix de portée. Une clé RPC permet à un programme d'appeler l'API d'Odoo ; relier un assistant à cette API demande un développement. L'API elle-même est présentée dans XML-RPC est déprécié : passer à l'API JSON-2 d'Odoo 20.

Points de vigilance

La clé vaut le compte

Odoo l'écrit dans la fenêtre de création : la clé « grants full access to your account », elle donne un accès complet au compte. Une clé d'administrateur confiée à un assistant lui ouvre toute la base, et toutes ses sociétés autorisées. La description du module ajoute que quiconque obtient la clé peut utiliser le serveur MCP comme s'il était l'utilisateur. Une clé par personne, à son nom, avec la durée la plus courte possible ; jamais dans un fichier partagé, et, dans l'assistant, dans un champ de type mot de passe plutôt que dans un champ texte.

L'assistant écrit sous votre nom

Le contact créé par l'assistant apparaît dans le fil de discussion comme créé par l'utilisateur de la clé, sans autre mention. Avant de cocher Disponible en MCP sur un outil d'écriture, décidez qui en a besoin ; un utilisateur aux droits restreints limite aussi ce que l'assistant peut modifier.

L'enregistrement libre ouvre la porte à tout assistant

Cocher Allow Dynamic Client Registration (DCR) permet à n'importe quelle application de s'enregistrer comme assistant et de demander un accès. La documentation d'Odoo indique qu'un client enregistré se bloque en l'archivant, en mode développeur, dans Paramètres › Technique › OAuth Clients. Laissez la case décochée tant que les assistants de la liste suffisent.

Exercice

Objectif : vérifier qu'un assistant connecté par MCP répond avec vos droits.

Indication : créez une clé de portée MCP valable 1 Day, déclarez le serveur dans Claude Code comme à l'étape 4, puis demandez-lui combien de devis et de commandes ont votre nom comme vendeur.

Critère de réussite : le nombre annoncé est celui de Ventes › Commandes › Devis, avec le filtre Mes devis posé d'office. Après suppression de la clé dans Mes préférences › Sécurité, l'assistant ne parvient plus à interroger Odoo.

À retenir

  • Odoo 20 Enterprise contient un serveur MCP, à l'adresse de la base suivie de /mcp, installé avec l'application IA.
  • Un assistant s'y connecte par OAuth (page Grant Access) ou par une clé API de portée MCP créée dans Mes préférences › Sécurité.
  • Il agit toujours au nom d'un utilisateur, avec ses droits : un commercial limité à ses documents obtient moins de réponses qu'un administrateur.
  • Cinq outils de lecture sont exposés d'office ; écrire suppose de cocher Disponible en MCP sur un outil d'écriture.
  • Supprimer la clé, dans Mes préférences › Sécurité, retire l'accès aussitôt.
