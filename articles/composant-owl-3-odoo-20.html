Un composant OWL 3 de A à Z en Odoo 20 : props, état, hooks, gabarit

Un annuaire express des sociétés, ouvert depuis le menu d'Odoo 20 : un composant parent qui charge et filtre, un composant enfant qui affiche une carte et remonte le clic sur l'étoile. Chaque brique d'OWL 3 y passe, avec un test Hoot et ce qui casse quand on l'écrit comme en Odoo 19.

~12 minutes de lecture · niveau intermédiaire · parcours Web et interface

Ce que tu vas apprendre

Découper

Un parent et un enfant : des props typées avec useProps et t, une valeur par défaut, un rappel qui remonte l'action de l'enfant vers le parent.

Réagir

L'état avec proxy, une valeur dérivée avec computed, une référence avec signal.ref(), et les hooks dans l'ordre où OWL 3 les appelle.

Vérifier

Quatre tests Hoot, et les erreurs exactes que produit le code écrit à la manière d'Odoo 19.

Prérequis

  • Une base Odoo 20 Community, avec les données de démonstration pour avoir des sociétés à afficher. Le module ne dépend que de web : aucune application à installer.
  • Savoir créer et installer un module (voir Installer Odoo 20 sur Ubuntu et le lancer dans PyCharm).
  • Un navigateur récent. Aucun outil JavaScript à installer : Odoo assemble lui-même les fichiers du module.

Dans le badge de retard, un widget de champ n'affichait qu'une valeur fournie par la vue. Un écran complet demande plus : charger des données, garder un état, réagir à la saisie, se souvenir d'un choix.

L'exemple de cet article est une action client : un écran entièrement écrit en OWL, ouvert par un menu, sans vue liste ni formulaire. Il affiche les sociétés de la base, les filtre à la frappe et marque des favoris d'une étoile. Deux composants se partagent le travail.

Le module tient en huit fichiers :

2. L'enfant : une carte, trois props validées

On commence par le plus simple. ContactCard ne charge rien et ne garde aucun état : elle affiche ce que le parent lui donne. Ce sont ses props. Quand on clique sur l'étoile, elle prévient le parent par une fonction reçue elle aussi en prop.

import { Component, t, useProps } from "@odoo/owl";

/** Carte d'une société : n'affiche que ce que le parent lui passe. */
export class ContactCard extends Component {
    static template = "oski_owl_annuaire.ContactCard";

    props = useProps({
        partner: t.object({ id: t.number(), name: t.string() }),
        isFavorite: t.boolean().optional(false),
        onToggleFavorite: t.function(),
    });

    toggle() {
        this.props.onToggleFavorite(this.props.partner.id);
    }
}
  • props = useProps({ … }) remplace le static props d'OWL 2. Chaque prop reçoit un type t : t.object({ id: t.number(), name: t.string() }) exige ces deux clés et accepte les autres (email, city), car t.object est un schéma ouvert.
  • t.boolean().optional(false) rend la prop facultative et lui donne une valeur par défaut. C'est la manière de déclarer un défaut avec useProps ; static defaultProps est refusé.
  • t.function() sans optional() rend le rappel obligatoire.

Le gabarit, dans le fichier XML voisin :

<?xml version="1.0" encoding="UTF-8"?>
<templates xml:space="preserve">

    <t t-name="oski_owl_annuaire.ContactCard">
        <div class="o_annuaire_card card h-100" t-att-class="{ 'border-warning': this.props.isFavorite }">
            <div class="card-body d-flex align-items-start gap-2">
                <div class="flex-grow-1">
                    <div class="o_annuaire_name fw-bold" t-out="this.props.partner.name"/>
                    <div t-if="this.props.partner.city" class="text-muted small" t-out="this.props.partner.city"/>
                    <a t-if="this.props.partner.email" class="small" t-att-href="'mailto:' + this.props.partner.email"
                       t-out="this.props.partner.email"/>
                </div>
                <button type="button" class="o_annuaire_star btn btn-link p-0" t-on-click="this.toggle"
                        t-att-title="this.props.isFavorite ? 'Retirer des favoris' : 'Ajouter aux favoris'">
                    <i class="oi fs-4 text-warning" t-att-class="{ 'oi-filled': this.props.isFavorite }" data-icon="star"/>
                </button>
            </div>
        </div>
    </t>

</templates>

Tout ce qui appartient au composant s'écrit avec this. : this.props.partner.name, t-on-click="this.toggle". En OWL 3, le gabarit n'hérite plus du composant. Son contexte ne contient que this (owl.js, ligne 3715 : { this: this.component, __owl__: this }).

L'icône est une icône Material (class="oi" data-icon="star", pleine avec oi-filled), comme le champ favori natif d'Odoo 20 : FontAwesome n'est plus chargé.

Les props ne sont vérifiées qu'en mode debug

Pour l'essai, on a retiré onToggleFavorite du gabarit du parent. En mode normal, les sept cartes s'affichent sans erreur. L'erreur n'arrive qu'au clic sur une étoile : TypeError: this.props.onToggleFavorite is not a function. Avec ?debug=1, l'écran s'arrête dès le premier rendu :

La validation dépend du mode de l'application OWL : dev: odoo.debug || session.test_mode (web/static/src/env.js, ligne 104). Développe donc en mode debug. Les tests Hoot tournent aussi dans ce mode : le troisième test, plus bas, s'en sert.

3. Le parent : l'état, une valeur dérivée, le gabarit

Annuaire fait le reste : il charge les sociétés, garde la recherche et les favoris, et dit à chaque carte ce qu'elle doit afficher. Voici le fichier complet :

import {
    Component,
    computed,
    onMounted,
    onWillStart,
    proxy,
    signal,
    useEffect,
    useListener,
    usePlugin,
    useProps,
} from "@odoo/owl";
import { browser } from "@web/core/browser/browser";
import { ORM } from "@web/core/orm_plugin";
import { registry } from "@web/core/registry";
import { standardActionServiceProps } from "@web/webclient/actions/action_plugin";
import { ContactCard } from "./contact_card";

export const FAVORITES_KEY = "oski_owl_annuaire.favoris";

function readFavorites() {
    try {
        return JSON.parse(browser.localStorage.getItem(FAVORITES_KEY)) || [];
    } catch {
        return [];
    }
}

export class Annuaire extends Component {
    static template = "oski_owl_annuaire.Annuaire";
    static components = { ContactCard };

    // 1. Props : celles que le gestionnaire d'actions passe à toute action client
    props = useProps({ ...standardActionServiceProps });
    orm = usePlugin(ORM);
    searchInput = signal.ref();

    setup() {
        // 2. État réactif : toute écriture redessine ce qui la lit
        this.state = proxy({
            partners: [],
            query: "",
            onlyFavorites: false,
            favoriteIds: readFavorites(),
        });
        // 3. Valeur dérivée, recalculée seulement quand ce qu'elle lit change
        this.visiblePartners = computed(() => {
            const query = this.state.query.trim().toLowerCase();
            return this.state.partners.filter(
                (p) =>
                    (!query || p.name.toLowerCase().includes(query)) &&
                    (!this.state.onlyFavorites || this.state.favoriteIds.includes(p.id))
            );
        });

        // 4. Hooks de cycle de vie
        onWillStart(async () => {
            this.state.partners = await this.orm.searchRead(
                "res.partner",
                [["is_company", "=", true]],
                ["name", "email", "city"],
                { order: "name" }
            );
        });
        onMounted(() => this.searchInput()?.focus());
        useEffect(() => {
            browser.localStorage.setItem(FAVORITES_KEY, JSON.stringify(this.state.favoriteIds));
        });
        useListener(browser, "keydown", (ev) => {
            // pas de raccourci pendant une saisie, dans la recherche ou ailleurs
            if (ev.key === "/" && !["INPUT", "TEXTAREA"].includes(ev.target.tagName)) {
                ev.preventDefault();
                this.searchInput()?.focus();
            }
        });
    }

    toggleFavorite(partnerId) {
        const ids = this.state.favoriteIds;
        const index = ids.indexOf(partnerId);
        if (index >= 0) {
            ids.splice(index, 1);
        } else {
            ids.push(partnerId);
        }
    }

    toggleOnlyFavorites() {
        this.state.onlyFavorites = !this.state.onlyFavorites;
    }
}

registry.category("actions").add("oski_owl_annuaire.annuaire", Annuaire);

OWL 3 repose sur des signaux : une valeur réactive se lit par un appel, x(), et tout rendu ou effet qui l'a lue est relancé quand elle change. proxy applique la même mécanique à un objet entier, propriété par propriété. Quatre briques sont à repérer :

  • Les props d'une action client. Le gestionnaire d'actions passe toujours action, et parfois actionId, state… Le cœur les réunit dans standardActionServiceProps (webclient/actions/action_plugin.js, lignes 101 à 109). Les déclarer donne la même validation qu'à l'enfant.
  • L'état : proxy(). Il remplace useState(), qui n'existe plus. Le proxy est profond : ids.push(…) ou ids.splice(…) dans toggleFavorite suffit à redessiner les cartes concernées.
  • La valeur dérivée : computed(). visiblePartners est une fonction : on la lit avec des parenthèses, this.visiblePartners(). Elle ne recalcule le filtre que si la recherche, la case « Favoris seulement », la liste ou les favoris ont changé.
  • La référence : signal.ref(). Elle remplace useRef("nom"). On la passe au gabarit par t-ref="this.searchInput" et on lit l'élément en l'appelant : this.searchInput(). Il n'y a plus de .el.

Le gabarit du parent :

<?xml version="1.0" encoding="UTF-8"?>
<templates xml:space="preserve">

    <t t-name="oski_owl_annuaire.Annuaire">
        <div class="o_action o_annuaire h-100 overflow-auto p-4">
            <h2 class="mb-3">Annuaire express</h2>
            <div class="d-flex flex-wrap align-items-center gap-3 mb-4">
                <input type="search" class="o_annuaire_search form-control" style="width: 20rem" placeholder="Rechercher une société (touche /)"
                       t-ref="this.searchInput" t-model.proxy="this.state.query"/>
                <button type="button" class="o_annuaire_only_fav btn"
                        t-att-class="this.state.onlyFavorites ? 'btn-warning' : 'btn-outline-secondary'"
                        t-on-click="this.toggleOnlyFavorites">Favoris seulement</button>
                <span class="o_annuaire_count text-muted">
                    <t t-out="this.visiblePartners().length"/> société(s) affichée(s),
                    <t t-out="this.state.favoriteIds.length"/> favori(s)
                </span>
            </div>
            <div t-if="this.visiblePartners().length" class="row g-3">
                <div class="col-12 col-md-6 col-xl-4" t-foreach="this.visiblePartners()" t-as="partner" t-key="partner.id">
                    <ContactCard partner="partner"
                                 isFavorite="this.state.favoriteIds.includes(partner.id)"
                                 onToggleFavorite.bind="this.toggleFavorite"/>
                </div>
            </div>
            <div t-else="" class="o_annuaire_empty alert alert-info">
                Aucune société ne correspond à « <t t-out="this.state.query"/> ».
            </div>
        </div>
    </t>

</templates>
  • t-model.proxy="this.state.query" relie le champ de saisie à l'état. Sans le suffixe .proxy, OWL 3 refuse le gabarit (voir l'encadré « Venant de la 19 »).
  • t-foreach exige un t-key. La variable de boucle partner n'appartient pas au composant : elle s'écrit sans this.
  • onToggleFavorite.bind="this.toggleFavorite" passe la méthode liée au parent. Quand la carte l'appelle, this désigne bien l'annuaire.

Les deux favoris de la seconde capture (Azure Interior et Wood Corner, masqué par le filtre) ont été posés avant de recharger la page. Ils sont revenus tels quels : le navigateur les avait gardés sous la clé oski_owl_annuaire.favoris, avec la valeur [16,9].

4. Les hooks : qui s'exécute, et quand

Un hook est une fonction appelée dans setup() qui accroche du code à un moment de la vie du composant. L'annuaire en utilise quatre :

HookDans l'annuairePourquoi là
onWillStart(async () => …)charge les sociétés par this.orm.searchRead(…)Le premier rendu attend la promesse : l'écran n'apparaît jamais vide.
onMounted(() => …)place le curseur dans la recherchePremier moment où l'élément existe dans la page.
useEffect(() => …)écrit les favoris dans localStorageSe relance seul quand ce qu'il lit change.
useListener(cible, "keydown", …)touche « / » → recherche (sauf pendant une saisie)L'écouteur est retiré à la destruction du composant, sans code de nettoyage.

Le chargement passe par le plugin ORM (usePlugin(ORM), de @web/core/orm_plugin). En Odoo 20, les services du client web sont devenus des plugins. useService("orm") marche encore, par un pont que le cœur marque comme temporaire.

Pour connaître l'ordre réel des appels, le module contient un test qui monte un composant « sonde ». Chaque hook y note son passage. Résultat, sur Odoo 20 :

MomentOrdre relevé
Montagesetup → useEffect (1er passage) → onWillStart → onMounted
Écriture dans l'étatnettoyage de l'effet → useEffect → onWillPatch → onPatched
Retrait par t-ifonWillUnmount → onWillDestroy → nettoyage de l'effet

useEffect n'attend plus le montage

En Odoo 19, useEffect(fn, () => [deps]) s'exécutait dans onMounted et onPatched, quand ses dépendances changeaient (owl.js de la 19.0, ligne 6212). En Odoo 20, c'est onWillDestroy(effect(fn)) (owl.js, lignes 1697 à 1699). L'effet tourne dès setup, avant tout élément dans la page. Il se relance quand une valeur réactive qu'il a lue change, et le second argument est ignoré. Un effet qui lit this.searchInput() reçoit null au premier passage, puis INPUT après onMounted, car la référence est elle-même un signal.

Pour toucher au DOM, utilise onMounted. La fonction que rend l'effet sert de nettoyage, avant chaque nouveau passage et à la destruction.

5. Tester avec Hoot

Hoot est le lanceur de tests JavaScript d'Odoo 20. mountWithCleanup monte un composant seul, sans menu ni action, et onRpc répond à la place du serveur. Le fichier complet :

import { expect, test } from "@odoo/hoot";
import { queryAllTexts } from "@odoo/hoot-dom";
import { animationFrame } from "@odoo/hoot-mock";
import {
    Component,
    onMounted,
    onPatched,
    onWillDestroy,
    onWillPatch,
    onWillStart,
    onWillUnmount,
    proxy,
    useEffect,
    xml,
} from "@odoo/owl";
import { browser } from "@web/core/browser/browser";
import { contains, mountWithCleanup, onRpc } from "@web/../tests/web_test_helpers";
import { Annuaire, FAVORITES_KEY } from "@oski_owl_annuaire/annuaire/annuaire";
import { ContactCard } from "@oski_owl_annuaire/annuaire/contact_card";

const PARTNERS = [
    { id: 16, name: "Azure Interior", email: "azure@example.com", city: "Fremont" },
    { id: 11, name: "Gemini Furniture", email: false, city: "Fairfield" },
    { id: 9, name: "Wood Corner", email: "wood@example.com", city: false },
];
const ACTION = { action: { type: "ir.actions.client", tag: "oski_owl_annuaire.annuaire" } };

function mockPartners() {
    onRpc("res.partner", "search_read", ({ kwargs }) => {
        expect.step(JSON.stringify(kwargs.domain));
        return PARTNERS;
    });
}

test("charge les sociétés au démarrage, filtre à la frappe", async () => {
    mockPartners();
    await mountWithCleanup(Annuaire, { props: ACTION });
    expect.verifySteps(['[["is_company","=",true]]']);
    expect(queryAllTexts(".o_annuaire_name")).toEqual(["Azure Interior", "Gemini Furniture", "Wood Corner"]);
    expect(".o_annuaire_search").toBeFocused();

    await contains(".o_annuaire_search").edit("wood");
    expect(queryAllTexts(".o_annuaire_name")).toEqual(["Wood Corner"]);

    await contains(".o_annuaire_search").edit("zzz");
    expect(".o_annuaire_card").toHaveCount(0);
    expect(".o_annuaire_empty").toHaveText("Aucune société ne correspond à « zzz ».");
});

test("l'étoile garde le favori dans le navigateur", async () => {
    browser.localStorage.setItem(FAVORITES_KEY, "[11]");
    mockPartners();
    await mountWithCleanup(Annuaire, { props: ACTION });
    expect.verifySteps(['[["is_company","=",true]]']);
    expect(".o_annuaire_card.border-warning .o_annuaire_name").toHaveText("Gemini Furniture");

    await contains(".o_annuaire_card:eq(0) .o_annuaire_star").click();
    expect(".o_annuaire_card.border-warning").toHaveCount(2);
    expect(browser.localStorage.getItem(FAVORITES_KEY)).toBe("[11,16]");

    await contains(".o_annuaire_only_fav").click();
    expect(queryAllTexts(".o_annuaire_name")).toEqual(["Azure Interior", "Gemini Furniture"]);
    expect(".o_annuaire_count").toHaveText("2 société(s) affichée(s), 2 favori(s)");
});

test("props validées : un rappel manquant est refusé", async () => {
    await expect(
        mountWithCleanup(ContactCard, { props: { partner: { id: 1, name: "Azure Interior" } } })
    ).rejects.toThrow(/Invalid component props \(ContactCard\)/);
});

test("ordre des hooks d'un composant", async () => {
    class Sonde extends Component {
        static template = xml`<span class="o_sonde" t-out="this.state.n"/>`;
        setup() {
            this.state = proxy({ n: 0 });
            expect.step("setup");
            useEffect(() => {
                expect.step(`effet n=${this.state.n}`);
                return () => expect.step("nettoyage de l'effet");
            });
            onWillStart(() => expect.step("onWillStart"));
            onMounted(() => expect.step("onMounted"));
            onWillPatch(() => expect.step("onWillPatch"));
            onPatched(() => expect.step("onPatched"));
            onWillUnmount(() => expect.step("onWillUnmount"));
            onWillDestroy(() => expect.step("onWillDestroy"));
        }
    }
    class Parent extends Component {
        static template = xml`<div><Sonde t-if="this.state.show"/></div>`;
        static components = { Sonde };
        setup() {
            this.state = proxy({ show: true });
        }
    }
    const parent = await mountWithCleanup(Parent);
    expect.verifySteps(["setup", "effet n=0", "onWillStart", "onMounted"]);

    const sonde = Object.values(parent.__owl__.children)[0].component;
    sonde.state.n = 1;
    await animationFrame();
    expect(".o_sonde").toHaveText("1");
    expect.verifySteps(["nettoyage de l'effet", "effet n=1", "onWillPatch", "onPatched"]);

    parent.state.show = false;
    await animationFrame();
    expect(".o_sonde").toHaveCount(0);
    expect.verifySteps(["onWillUnmount", "onWillDestroy", "nettoyage de l'effet"]);
});
  • Le composant est monté avec { props: ACTION } : action est obligatoire, et le test tourne en mode debug, où les props sont vérifiées.
  • onRpc reçoit le domaine dans kwargs.domain : searchRead le place dans les arguments nommés de search_read (core/orm_plugin.js, lignes 240 à 246).
  • Le module ne dépend que de web : pas de defineMailModels(), contrairement au widget de la Bibliothèque, qui dépend de mail.
  • Le troisième test vérifie le refus d'une prop manquante, le quatrième relève l'ordre des hooks du tableau précédent.

Venant de la 19 : ce qui casse, et comment

Chaque ligne a été essayée dans un test Hoot temporaire, sur la même base :

Écrit comme en 19Résultat en Odoo 20
import { useState, useRef } from "@odoo/owl"undefined (de même reactive, onRendered) → TypeError à l'appel. Remplaçants : proxy, signal.ref().
t-out="state.query"TypeError: Cannot read properties of undefined (reading 'query') au montage.
t-out="title" (membre du composant)Rien d'affiché, aucune erreur.
t-model="this.state.query"OwlError: Invalid t-model expression: expression should evaluate to a function with a 'set' method defined on it → t-model.proxy.
t-ref="searchInput"OwlError: Ref is undefined or null → t-ref="this.searchInput" sur un signal.ref().
static props = { … }Ignoré : une prop requise absente passe sans erreur, même en debug.
static defaultProps = { … }Error: Component "…" defines a static "defaultProps", which Owl 3 ignores… → t.x().optional(valeur).

Les deux lignes qui ne lèvent rien sont les plus coûteuses : un texte qui manque, une prop jamais vérifiée. La version d'OWL embarquée par Odoo 20 est la 3.0.0-alpha.49 (owl.js, ligne 1776).

À retenir

  • Un composant OWL 3 se déclare toujours de la même façon : useProps pour ce qu'il reçoit, proxy et computed pour ce qu'il garde, des hooks dans setup(), un gabarit où chaque membre prend this.
  • Les props ne sont vérifiées qu'en mode debug et dans les tests. Développe en ?debug=1.
  • useEffect tourne dès setup et suit tout seul ce qu'il lit. Ce qui touche au DOM va dans onMounted.
  • L'enfant ne modifie pas les données du parent : il appelle un rappel reçu en prop, et c'est le parent qui écrit dans son état.
  • Hoot vérifie le composant seul, sans serveur : mountWithCleanup et onRpc, filtre "@module".
